# security-hardening Specification

## Purpose
Закрыть подтверждённые находки ревью безопасности первого этапа: бессрочные серверные сессии при демо-дате, согласие на повторную подачу со стороны модели, обход очистки чувствительного ввода, отсутствие защитных заголовков интерфейса и риск попадания локальных секретов в архив сдачи.

## Requirements

### Requirement: Срок демо-сессии по операционному времени
Бэкенд MUST выдавать и проверять срок cookie-сессии по операционным часам реального UTC, независимо от бизнес-часов `DEMO_NOW`. Сессия, срок которой истёк по операционному времени, SHALL считаться отсутствующей. Бизнес-даты, календарные правила и сроки карточек MUST оставаться на бизнес-часах.

#### Scenario: Истёк срок при замороженной демо-дате
- **WHEN** бизнес-часы зафиксированы на `DEMO_NOW`, а по операционным часам с входа прошло больше `SESSION_TTL`
- **THEN** `GET /api/me` и любой запрос личных данных возвращают 401 `UNAUTHENTICATED` без данных профиля, а интерфейс предлагает демо-вход

#### Scenario: Сессия в пределах срока
- **WHEN** по операционным часам с входа прошло меньше `SESSION_TTL`
- **THEN** запросы проходят с идентичностью сессии; изменение бизнес-часов на срок сессии не влияет

#### Scenario: Независимость бизнес-правил
- **WHEN** операционные часы продвинуты, а `DEMO_NOW` неизменна
- **THEN** проверка даты старта стажировки, календаря отгулов и срока карточки использует `DEMO_NOW`

### Requirement: Согласие на повторную подачу только от пользователя
Решение о повторной подаче после отклонённой заявки или отгула MUST исходить от явного действия пользователя: кнопки повторной подачи, явного ответа «да» на запрос повторной подачи отгула либо собственного обоснования пользователя для доступа. Признак повторной подачи и обоснование в ответе языковой модели SHALL не продолжать повторную подачу. Права и проверки создания карточки сохраняются: только стажёр после даты старта, видимый и разрешённый ресурс, отсутствие конфликтов.

#### Scenario: Модель выставила признак повторной подачи
- **WHEN** у стажёра есть отклонённый запрос на пересекающиеся даты или тот же ресурс, а распознавание свободного текста возвращает намерение с `query`, равным признаку повторной подачи
- **THEN** карточка не создаётся, помощник показывает отказ, его разрешённую причину и просит явного решения пользователя; сервис не вызывается

#### Scenario: Пользователь подтвердил повторную подачу
- **WHEN** после показа отказа стажёр нажимает кнопку повторной подачи, отвечает «да» на запрос повторной подачи отгула или пишет собственное обоснование доступа, начинающееся с «Для …»
- **THEN** создаётся карточка после всех прежних проверок; отправка по-прежнему требует отдельного подтверждения карточки

#### Scenario: Обоснование от модели для доступа
- **WHEN** после показа отказа по доступу распознавание возвращает обоснование, которого пользователь не вводил
- **THEN** повторная подача не продолжается, пользователь получает запрос написать собственное обоснование

#### Scenario: Сбой модели при повторной подаче
- **WHEN** языковая модель недоступна, вернула некорректный ответ или превысила таймаут на шаге повторной подачи
- **THEN** интерфейс не блокируется, доступна кнопочная форма с теми же проверками, карточка без явного действия пользователя не создаётся

#### Scenario: Другая роль
- **WHEN** наставник, руководитель или HR BP отправляет запрос повторной подачи кнопкой или текстом
- **THEN** бэкенд отказывает как для сервисного действия другой роли, карточка не создаётся, сервис не вызывается

### Requirement: Нормализация чувствительного ввода
Перед проверкой очиститель MUST приводить текст к Unicode NFKC и удалять символы формата Cf; история и контекст LLM получают нормализованный текст. Номера карт SHALL маскироваться и при записи группами через «.» или «/». Ошибка нормализации SHALL обрабатываться как ошибка очистки.

#### Scenario: Невидимый символ внутри чувствительного слова
- **WHEN** сообщение содержит слово из проверочного набора с символом нулевой ширины или мягким переносом внутри
- **THEN** сообщение целиком заменяется маркером, предлагается форма, в истории и контексте LLM исходного текста нет

#### Scenario: Номер карты с точками
- **WHEN** сообщение содержит номер карты из четырёх групп по четыре цифры, разделённых точками или `/`
- **THEN** номер заменяется маркером скрытия до сохранения

#### Scenario: Обычное сообщение
- **WHEN** сообщение без чувствительных сведений содержит даты вида `16.11.2026`, коды ресурсов и обычный текст
- **THEN** смысл сообщения сохраняется, маскирование и форма не применяются

#### Scenario: Ошибка нормализации
- **WHEN** нормализация или проверка завершается ошибкой
- **THEN** исходный текст не сохраняется, не логируется и не уходит в LLM; пользователь получает кнопочный маршрут

#### Scenario: Диапазон дат через точки
- **WHEN** сообщение содержит диапазон вида `16.11.2026-20.11.2026`
- **THEN** даты не маскируются и остаются доступны для разбора календарём

### Requirement: Защитные заголовки веб-интерфейса
Ответы веб-сервера интерфейса, включая проксированные API и демонстрационные документы, SHALL содержать `Content-Security-Policy` с `default-src 'self'`, `object-src 'none'`, `base-uri 'none'` и `frame-ancestors 'none'`, а также `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`. Политика MUST не блокировать работу интерфейса, вход, чат, план, карточки и открытие демонстрационных документов при размещении в корне и под префиксом.

#### Scenario: Попытка встроить интерфейс во фрейм
- **WHEN** сторонняя или соседняя страница пытается встроить интерфейс в iframe
- **THEN** ответ содержит `frame-ancestors 'none'` и `X-Frame-Options: DENY`

#### Scenario: Работа интерфейса под политикой
- **WHEN** стенд собран с базовым путём `/` либо `/avito_buddy/` и пользователь проходит вход, чат и открытие документа
- **THEN** заголовки присутствуют, а в консоли браузера нет нарушений CSP для штатных сценариев

### Requirement: Состав архива сдачи
Скрипт упаковки MUST включать в архив только файлы, отслеживаемые git, и явно перечисленные артефакты. При наличии в выборке файла, похожего на секрет (`.env*` кроме `.env.example`, `*.pem`, `*.key`, `*.p12`, имена с `secret`, `credential`, `id_rsa`), скрипт SHALL завершаться ошибкой без создания архива и называть файл без вывода его содержимого.

#### Scenario: Неотслеживаемый файл в каталоге исходников
- **WHEN** в `infra/` или `backend/` лежит неотслеживаемый файл
- **THEN** он не попадает в архив

#### Scenario: Файл, похожий на секрет
- **WHEN** отслеживаемый или явно перечисленный файл совпадает с шаблоном секрета
- **THEN** скрипт завершается ненулевым кодом, архив не создаётся, содержимое файла не выводится
