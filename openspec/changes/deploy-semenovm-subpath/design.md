# Design

## Context

На сервере 177.202.73.214 уже работают nginx, TLS для semenovm.ru и другие приложения. UI использует корневой маршрут TanStack Router, Vite base по умолчанию и абсолютные ссылки документов; API имеет переменную VITE_API_BASE_URL.

## Goals / Non-Goals

**Goals:** минимальные настраиваемые URL и изолированное развёртывание существующего прототипа.

**Non-Goals:** изменение серверных контрактов, доменных правил и интеграций.

## Decisions

- Vite base из VITE_BASE_PATH; Router использует BASE_URL. API по умолчанию берёт тот же префикс с сохранением отдельного VITE_API_BASE_URL. Внутренние ссылки документов получают префикс через общий helper с unit-тестами.
- Внешний nginx удаляет `/avito_buddy/` при проксировании на frontend; вложенный nginx сохраняет существующий контракт `/api/`. Cookie Path переписывается внешним nginx в `/avito_buddy/`.
- Compose override убирает публикацию БД/Redis/API/mocks и выделяет loopback-порт 25173 для UI. Все сервисы имеют restart unless-stopped. Панель ведущего остаётся доступна через SSH-туннель и docker network, публично не публикуется.
- Собираем Linux amd64 Go-бинарники и frontend локально, на сервер передаём исходники и подготовленные артефакты без .env и пользовательских файлов; runtime-образы не требуют компиляторов на сервере с 2 ГБ RAM. Секреты генерируем на сервере.

## Risks / Trade-offs

- Публичный demo-вход доступен всем → только синтетические данные, fake LLM, панель ведущего закрыта.
- Общий nginx → резервная копия, nginx -t перед reload, проверка существующих адресов.
- Ошибка обновления → предыдущие runtime-артефакты и конфигурация сохраняются; тома не удаляются.

## Migration Plan

Сборка и тесты, передача в /opt/avito-buddy, создание .env, Compose up --wait, подключение nginx location, HTTPS smoke и браузерная проверка. Откат: восстановить резервную копию nginx, reload, остановить только новый Compose-проект без удаления томов.
