# Proposal

## Why

Автоматические проверки должны брать на себя форматирование, типовые дефекты, регрессии бизнес-логики и воспроизводимые сбои, освобождая ревьюера для анализа безопасности данных и архитектурных инвариантов. Существующие тесты доступа, отсутствий и онбординга дают основу, но не объединены с линтерами, поиском секретов, фаззингом и проверкой полноты прогона в один проверяемый контракт.

## What Changes

- Добавить локальные профили `make review-fast` и `make review-deep`, единый машинный отчёт и краткую сводку для агента без сырых секретов и длинных успешных логов.
- Зафиксировать совместимые версии инструментов: golangci-lint, govulncheck, Gitleaks; использовать встроенные Go vet, race detector и fuzzing. IDE-расширения оставить необязательной оболочкой над теми же проверками.
- Усилить тесты по матрице бизнес-инвариантов: авторизация, отзыв прав, подтверждение, конкурентные операции, неизвестный исход, повтор, восстановление и границы времени.
- Добавить тестирование свойств и ограниченный по времени фаззинг схем, календаря и обработки входа; сохранять безопасные регрессионные примеры.
- Подготовить GitHub Actions для PR, ручного и периодического глубокого прогона, с ограниченными правами и изолированными тестовыми сервисами. Публикацию файлов, запуск удалённого CI и настройки GitHub выполняет человек.
- Зафиксировать ADR о выборе инструментов и бюджетах, регламент интерпретации результатов и оставшуюся область ручного ревью.

## Capabilities

### New Capabilities

- `backend-verification`: воспроизводимые профили автоматической проверки Go-модулей, полнота исполнения, бизнес-инварианты и безопасные отчёты.

### Modified Capabilities

Нет. Основные спеки пока не архивированы; этот контракт дополняет проверку из `build-onboarding-prototype/specs/prototype-verification/spec.md`, сохраняя требование покрытия каждого модуля строго >80%.

## Impact

Планируемые файлы: `Makefile`, `.golangci.yml`, `.gitleaks.toml`, `scripts/review/`, тесты `backend/` и при необходимости `mocks/`, `.github/workflows/backend-review.yml`, `docs/verification/backend-review.md`, новый ADR и README. Runtime-зависимости и публичные API не меняются; реальные LLM не вызываются. Сценарии стажёра сохраняются, уменьшается ручная повторная проверка наставником и командой разработки.

Вне области: исправление обнаруженных продуктовых дефектов без отдельного согласования, установка глобальных IDE-плагинов, платные сервисы, передача исходников внешним сканерам, изменение deployment, настройка защиты веток, git commit/push/PR и заявление о полной защищённости.
