# Design

## Context

См. proposal. Сервер выдаёт снимки и упорядоченные события, клиент опрашивает активный маршрут раз в секунду. `ExecutionMap` показывает снимок целиком, `useEventMotion` перемещает маркер при изменении узла. Текущий незавершённый change `redesign-buddy-experience` запрещает очередь движения: данное предложение меняет это правило только для явно обозначенного воспроизведения, сохраняя немедленный показ актуального результата.

## Goals / Non-Goals

**Goals:** различимая композиция плана; наглядный последовательный путь; фактический статус отдельно от анимированной истории; доступность и мобильная вёрстка.

**Non-Goals:** менять время серверной обработки, API, права, синтетические данные или включать проигрывание сохранённой истории после перезагрузки.

## Decisions

1. Очередь представления строится только по полученным серверным событиям нового маршрута и дедуплицируется по идентификатору/последовательности. Отдельный актуальный статус и результат берутся непосредственно из снимка. При склейке быстрых событий история анимируется примерно по секунде на подтверждённый этап с подписью «Показываем пройденный путь». Альтернатива — замедлять запрос или выдавать историю за активные вызовы — искажает факты.
2. Активный текущий этап подсвечивается, импульс движется по связи; для завершённой истории импульс представляет только визуальное воспроизведение. При отсутствии свежих данных, ошибке, смене профиля/запроса или reduced motion таймеры и эффекты останавливаются; снимок остаётся доступен. При первом открытии сохранённого маршрута история не проигрывается.
3. Компактная и подробная карты используют одно фактическое состояние, а воспроизведение имеет одну управляемую сессию на маршрут; раскрытие окна не перезапускает его. Мобильный путь вертикален, длинные названия переносятся. Оформление плана сохраняет текущий порядок и бизнес-действия.
4. CSS/SVG используются для связей и свечения, без новых зависимостей. Текстовые статусы остаются доступны независимо от анимации и цвета. Не добавлять мигание; предпочтения движения проверяются при запуске и изменении настройки.

## Risks / Trade-offs

- [История выглядит текущей работой] → явная подпись воспроизведения и отдельный немедленный фактический статус.
- [События приходят пачкой или повторяются] → стабильный порядок, дедупликация и тесты; не анимировать неподтверждённые этапы.
- [Очередь накапливается или становится неактуальной] → немедленное отображение результата, ограниченная очередь, сброс при смене контекста и переходе в stale.
- [Конфликт незавершённых спецификаций] → перед архивированием согласовать порядок изменений и заменить прежний запрет очереди в `redesign-buddy-experience`, не ослабляя требования достоверности.

## Migration Plan

После утверждения реализовать фронтенд и тесты, проверить на синтетическом стенде. Откат — вернуть прежнее представление и движение; серверные данные и операции не мигрируются.
