# Proposal

## Why

Ревью безопасности от 15.11.2026 ([output/security-review/report.md](../../../output/security-review/report.md)) нашло один дефект P2 и пять P3; дефектов P0/P1 нет. Три из них подтверждены падающими тестами:

- Серверный срок демо-сессии считается по замороженным бизнес-часам `DEMO_NOW`, поэтому сессия на сервере не истекает (SR-01, P2).
- Ответ модели через слот `query` может пропустить шаг явного согласия на повторную подачу после отказа (SR-02).
- Локальный очиститель чувствительного ввода обходится невидимыми символами и номерами карт через точку (SR-03).

Отдельно зафиксированы по конфигурации: отсутствие защитных HTTP-заголовков (SR-04) и сборка архива сдачи по denylist (SR-05).

Изменение закрывает первый этап этих находок. Стажёр получает предсказуемое завершение сессии на общем компьютере и гарантию, что повторную подачу после отказа запускает только он сам. Наставнику не приходится разбирать спорные повторные заявки, созданные без явного решения стажёра. Жюри видит укреплённый стенд и воспроизводимые тесты на каждую находку.

## What Changes

- Срок cookie-сессии API выдаётся и проверяется по операционным часам реального UTC независимо от `DEMO_NOW`. Бизнес-часы по-прежнему управляют датами, правилами и сроками карточек.
- Признак повторной подачи принимается только от явного действия пользователя (кнопка или явный ответ на запрос повторной подачи). Значение из ответа модели отбрасывается. Обоснование, придуманное моделью, не продолжает повторную подачу доступа.
- Очиститель перед проверкой нормализует текст (Unicode NFKC, удаление символов формата Cf) и дополнительно распознаёт номера карт группами по четыре цифры через «.» или «/» (прежние разделители «пробел» и «-» сохраняются).
- Ответы frontend-nginx получают заголовки `Content-Security-Policy` (в том числе `frame-ancestors 'none'`), `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`.
- `scripts/package-submission.py` собирает архив из `git ls-files` и явного списка артефактов и прерывается при файле, похожем на секрет.
- ADR 0008 дополняется оставшимися ограничениями очистителя. В документацию по деплою добавляются рекомендации SR-06 и вынос стенда на отдельный поддомен.

## Capabilities

### New Capabilities

- `security-hardening`: срок сессии по операционному времени, согласие на повторную подачу только от пользователя, нормализация чувствительного ввода, защитные заголовки интерфейса и безопасный состав архива сдачи.

### Modified Capabilities

Нет. Основные спеки ещё не архивированы. Изменение уточняет требования `build-onboarding-prototype` (`identity-and-permissions`: «Системная идентичность», «Минимизация чувствительного содержимого»; `assistant-dialogue`: «Намерения и уточнения») и не противоречит им.

## Impact

Файлы:

- `backend/internal/api/session.go`, `backend/internal/api/processing.go`, `backend/internal/app/app.go`;
- `backend/platform/safety/text.go`, `backend/go.mod` (`golang.org/x/text` из indirect в direct, версия v0.24.0 уже зафиксирована в go.sum);
- `frontend/nginx.conf`, `scripts/package-submission.py`;
- тесты рядом с изменённым кодом, `docs/adr/0008-sensitive-input.md`, `docs/deployment.md`.

Схема БД, публичные API и данные не меняются. Видимый эффект для пользователя: через `SESSION_TTL` (по умолчанию 8 ч) реального времени нужен повторный демо-вход. Сообщения со скрытыми символами внутри чувствительных слов теперь закрываются маркером и формой.

Вне области:

- раздельные роли PostgreSQL, ACL Redis и непривилегированный nginx (SR-06) — только рекомендации в документации;
- перенос стенда на поддомен и изменения внешнего nginx и DNS сервера;
- свёртка латинских гомоглифов и разрядки в очистителе;
- rate limiting;
- изменения деплоя на semenovm.ru;
- git commit/push/PR.
