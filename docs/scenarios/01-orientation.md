# Сценарий 1. Ориентирование: следующий шаг и ответ по материалам

> Общие механизмы — [00-common.md](00-common.md) (ссылки вида M-…). Демо-данные — [M-0](00-common.md#m-0-демо-данные-на-которых-показаны-примеры).

## Проблема

Стажёр не знает, что важнее сделать сейчас, где лежит инструкция и к кому идти. Он спрашивает наставника о том, что есть в плане и материалах. Сценарий снимает эти организационные вопросы с наставника и оставляет ему содержательную работу.

## Границы

- **Входит:** выбор следующего шага, объяснение шага, поиск ответа в разрешённых материалах со ссылкой, подсказка ответственного, вопрос о целях (без самих целей), отметка своего шага (M-17).
- **Не входит:** выполнение шагов других людей, оценка стажёра, постановка целей, пересказ материалов других команд, ответы «из головы» модели без источника.
- Ответ в чате **не меняет статус шага**. Статус меняется только через M-17 или ответ сервиса.

## O-1. С чего начать

### Как выбирается шаг

Шаг выбирает **код**, не LLM. LLM только объясняет выбор своими словами. Без LLM ответ строится по шаблону (M-11).

1. Кандидаты: шаги, где **владелец — стажёр**, состояние не «выполнен», шаг не заблокирован.
2. Порядок групп:
   1. «требует внимания» (отказ сервиса, неизвестный исход);
   2. просроченные: период шага уже прошёл;
   3. «в работе» текущего периода;
   4. «не начат» текущего периода;
   5. шаги следующего периода — с пометкой «можно начать заранее».
3. Внутри группы: сначала шаги, от которых зависят другие (P6 открывает P7), затем — порядок плана.
4. В ответе: **один главный шаг** + до двух следующих.
5. Отдельно — блок «Ждём от других»: шаги текущего периода, где владелец — другой человек и шаг не выполнен (до трёх). Они не подаются как долг стажёра.
6. Если кандидатов нет: «Все твои шаги на этот период выполнены» + блок «Ждём от других» + шаги следующего периода, если есть.

### Что в ответе

- главный шаг: название, почему сейчас (группа из п. 2 человеческими словами), что сделать, источник (план адаптации / чек-лист, демо);
- быстрые действия к шагу: `[Запросить доступ]` для P6, `[Отметить выполненным]` для шагов стажёра, `[Где инструкция?]`;
- следующие шаги — одной строкой каждый;
- «Ждём от других» — шаг и человек.

### Маршрут

```
Триггер → бэкенд: профиль, период, план, статусы сервисов (M-8)
  ├─ статус сервиса недоступен → используем последний известный + «по данным на …»
  ├─ есть кандидаты → главный шаг + 2 следующих + «ждём от других»
  ├─ кандидатов нет → «всё выполнено» + следующий период / «ждём от других»
  └─ LLM недоступна → тот же список шаблоном (M-11)
→ стажёр выбирает действие:
  ├─ [Запросить доступ] → сценарий 02 (ресурс = пространство команды)
  ├─ [Отметить выполненным] → M-17
  ├─ [Где инструкция?] → O-2 с темой шага
  └─ свободный текст → M-2
```

### Диалог 1.1 — стажёр А, 1-я неделя

Состояние: P4 выполнен (Алина отметила 10.11), P5 не начат, P6 не начат, P7 заблокирован, P1 у наставника не выполнен, P3 у руководителя не начат.

```

🤖 AI-buddy: Сейчас у тебя 1-я неделя. Главное на сегодня — запросить доступ в пространство команды «Платежи».
   От него зависит следующий шаг — изучить пространство: там документы команды.
   Источник: план адаптации (по чек-листу стажёра, демо).
   [Запросить доступ] [Где инструкция?]

   Дальше по плану:
   • Завести конспект встреч с наставником
   • Изучить пространство команды — откроется после доступа

   Ждём от других:
   • Добавить тебя в чаты и каналы — Игорь Белов (наставник)
   • Обсудить цели и план адаптации — Ольга Миронова (руководитель)
```

### Диалог 1.2 — стажёр Б, тот же вопрос, 2-я неделя

Состояние: P4, P6 выполнены, P5 не выполнен (1-я неделя прошла), P7 в работе, P9 и шаг команды «Изучи библиотеку компонентов (демо)» не начаты.

   Дальше по плану:

| # | Условие | Реакция | Итог |

| O-1.2 | кандидатов нет, есть следующий период | «всё выполнено» + шаги следующего периода | ответ |
| O-1.3 | кандидатов нет и следующего периода нет | «все шаги первых недель выполнены»; в прототипе поздние этапы не ведутся | ответ |
| O-1.4 | главный шаг закрывается сервисом и по нему есть открытая заявка | показать статус заявки вместо «сделай»: «Заявка ACC-1042 на рассмотрении — ждём согласующего» | ответ; шаг в «ждём от других» |

| O-1.7 | LLM недоступна | шаблонный список того же содержания | ответ |
| O-1.8 | стажёр не согласен («это я уже сделал») | предложить M-17 для шагов стажёра; для чужих — «это отмечает наставник» | M-17 или ответ |
| O-1.9 | «а почему именно это?» | объяснение правила выбора: группа, зависимость, период | ответ |
| O-1.10 | «покажи весь план» | ссылка на панель плана, без пересказа всех шагов | ответ |

## O-2. Найти инструкцию или ответ по материалам

### Маршрут

```
Вопрос → бэкенд: права → поиск только по разрешённым документам
  ├─ вопрос слишком общий («расскажи про инструмент») → M-3: «Про какой?» + кнопки из плана
  ├─ найден 1 подходящий документ → ответ по нему + ссылка + «демо»
  ├─ найдено несколько → короткий ответ + список до 3 ссылок
  ├─ найден только устаревший → не пересказываем как правило; показываем владельца
  ├─ ничего не найдено → «подтверждённой инструкции нет» + ответственный (O-3)
  ├─ подходящий документ есть, но закрыт (другая команда, скрытый) → как «не найдено» (M-10)
  └─ LLM недоступна → список найденных ссылок без пересказа (M-11)
→ ответ всегда со ссылкой; вывод LLM сверяется с найденными фрагментами
→ если вопрос ведёт к действию («как оформить отгул?») → предложить действие
```

### Правила ответа

- В контекст LLM попадают **только** фрагменты разрешённых документов и план пользователя.
- Каждое утверждение — из найденного фрагмента. Нет фрагмента — нет утверждения.
- Демо-материалы помечаются: «(демонстрационная инструкция)». Пересказ Playbook — ссылкой на открытый источник.
- Ответ короткий: 2–5 предложений + ссылка. Пересказывать весь документ не нужно.

### Диалог 2.1 — один вопрос, разные команды

```

🤖 AI-buddy: В команде «Платежи» для этого есть документ «Как команда „Платежи“ пишет код» (демонстрационная инструкция).
   Коротко: ревью обязательно для каждого изменения, тесты пишутся вместе с кодом, большие изменения разбиваются на части.
   📄 Как команда «Платежи» пишет код (демо)
```

```
👤 Максим: Где почитать, как у нас пишут код?
🤖 AI-buddy: Для фронтенда в команде «Поиск» начни с «Как пользоваться библиотекой компонентов» (демонстрационная инструкция):
   там описано, какие компоненты брать и как предлагать новые.
   📄 Как пользоваться библиотекой компонентов (демо)
```

## O-3. К кому обратиться

Справочник ответственных строится из профиля (наставник, руководитель, куратор) и каталога (согласующие ресурсов).

| Тема | Ответственный |
|---|---|
| чаты, каналы, 1:1, рабочее окружение, задачи | наставник |
| цели, ожидания, критерии стажировки, отгул (согласование) | руководитель |
| программа стажировки, отпуск, больничный, бенефиты, документы | куратор (HR BP) |
| доступ к конкретному ресурсу | согласующий ресурса из каталога |
| не определено | наставник по умолчанию |

```
👤 Алина: Кому писать, чтобы меня добавили в чат команды?
🤖 AI-buddy: Это делает наставник — Игорь Белов. В твоём плане это его шаг «Добавить стажёра в чаты и каналы», сейчас не выполнен.
   Можешь напомнить ему на ближайшей встрече или в личных сообщениях.
```

Агент **не пишет** людям от имени стажёра — показывает только контакт и шаг.

## O-4. Вопрос о целях

Цели ставит руководитель на 1-й неделе. Агент цели не хранит и не придумывает.

```
👤 Алина: Какие у меня цели на стажировку?
🤖 AI-buddy: Цели ставит руководитель — Ольга Миронова. В плане это шаг «Обсудить цели и план адаптации» на 1-й неделе, сейчас он не начат.
   Придумывать цели за руководителя я не буду. Полезно прийти на встречу с вопросами: какие задачи ждут в первые месяцы и по каким критериям оценят стажировку.
```

Если шаг P3 выполнен: «Цели вы обсудили с Ольгой Мироновой 11.11. Их текст в AI-buddy не хранится — посмотри свои записи или конспект».

## Нестандартные ситуации

| Ситуация | Поведение |
|---|---|
| Стажёр спрашивает про чужой план («что у Максима?») | M-19: не показываем |
| Вопрос во время открытой карточки другого сценария | ответ + напоминание о черновике (M-4) |
| Подряд два непонятных сообщения | M-3, п. 5 |
| Профиль без команды (ошибка данных) | общий план и общие документы + «Не вижу твою команду в профиле — уточни у куратора: Дарья Лебедева» |
| Дата старта в будущем | «Твоя стажировка начинается 16.11 — вот что будет на 1-й неделе» (план только для чтения) |
| «Ты кто?» / «Что ты умеешь?» | короткое описание + кнопки возможностей |

## Конечные состояния

| Код | Чем закончилось |
|---|---|
| O-E1 | показан следующий шаг и источник |
| O-E2 | показан ответ со ссылкой на разрешённый документ |
| O-E3 | честное «нет инструкции» + ответственный |
| O-E4 | переход в действие (02, 03, M-17) |
| O-E5 | шаблонный ответ при недоступной LLM |
| O-E6 | отказ: вне рамок или нет прав |

## Критерии приёмки (основа для OpenSpec)

1. WHEN стажёр А и стажёр Б задают «С чего начать?» THEN каждый получает главный шаг своего периода и своей команды, а шаги другого человека не подаются как его долг.
2. WHEN в плане есть шаг в состоянии «требует внимания» THEN он показывается главным.
3. WHEN LLM недоступна THEN ответ на «С чего начать?» содержит тот же главный шаг (шаблон).
4. WHEN стажёр «Платежей» задаёт вопрос, ответ на который есть только в документе «Поиска», THEN документ «Поиска» не попадает в контекст LLM, а ответ — «инструкции нет» + ответственный.
5. WHEN найден только устаревший документ THEN его содержание не подаётся как правило.
6. WHEN документ содержит инструкцию агенту THEN ни один инструмент не вызывается.
7. WHEN агент ответил на вопрос о шаге THEN статус шага не изменился.
8. Каждый ответ по материалам содержит ссылку на источник и пометку «демо» для демо-материалов.
