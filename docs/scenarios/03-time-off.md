# Сценарий 3. Запрос на отгул

> Общие механизмы — [00-common.md](00-common.md) (M-…). Демо-данные — [M-0](00-common.md#m-0-демо-данные-на-которых-показаны-примеры). «Сегодня» — **чт, 12 ноября 2026**.

## Проблема

Пример из кейса: стажёру нужен отгул. Он не знает, как его оформить, и не уверен, стоит ли отвлекать руководителя. AI-buddy объясняет процедуру, готовит запрос в сервис отсутствий и показывает результат. Личное общение с руководителем и наставником при этом остаётся.

## Основание

- Кейс: сервис отсутствий назван среди корпоративных сервисов; пример с отгулом — в описании проблемы.
- Реальные поля, порядок согласования и API в материалах не даны. В прототипе — **демонстрационная инструкция** и **имитация сервиса отсутствий**. Контракт имитации описывается в OpenSpec до реализации.

## Границы

- **Входит:** только тип «Отгул»; один день или несколько рабочих дней подряд; создание запроса; статус; отмена до первого дня; перенос (отмена + новый запрос).
- **Не входит:** отпуск, больничный, командировка, половина дня, «уйти пораньше», отгул за другого человека, причина отсутствия, комментарий руководителю, изменение дат существующего запроса одной операцией, автоматические сообщения наставнику.

## Демо-правила (демонстрационные, не регламент Авито)

Проверяются **кодом** до карточки и повторно при подтверждении.

| Код | Правило | Пример нарушения (сегодня чт, 12.11) |
|---|---|---|
| R1 | дата не в прошлом | «вчера», 10.11 |
| R2 | подать минимум за 1 рабочий день: первый день — не раньше следующего рабочего дня | «сегодня», 12.11 |
| R3 | первый и последний день — рабочие по демо-календарю; выходные и праздники внутри диапазона не считаются | сб, 14.11; чт, 31.12 (демо-праздник) |
| R4 | не больше 5 рабочих дней в одном запросе | 16.11–24.11 (7 рабочих дней) |
| R5 | последний день — не дальше 90 дней от сегодня (до 10.02.2027 включительно) | 15.03.2027 |
| R6 | нет пересечения с активными запросами («Отправлен», «На рассмотрении», «Согласован») и со спорными попытками | уже есть запрос на 13.11 |
| R7 | первый день не позже последнего | «с 20 по 16» |

Демо-календарь: выходные — сб и вс; праздники (демо) — 31.12.2026 и 01.01–08.01.2027.

## Статусы запроса (имитация)

| Статус | Значение |
|---|---|
| Отправлен | сервис принял запрос |
| На рассмотрении | руководитель открыл запрос |
| Согласован | руководитель согласовал |
| Отклонён | руководитель отказал, есть причина |
| Отменён | стажёр отменил |
| Результат уточняется / Нужна ручная проверка | M-7 |

Отгул не входит в чек-лист, поэтому шагом плана не является. Запросы видны в блоке плана «Мои заявки и запросы» с датами и статусом.

## Данные

| | Что | Как |
|---|---|---|
| Знает заранее | профиль, руководитель (согласующий), демо-календарь, демо-правила | M-1 |
| Получает сам | активные запросы и спорные попытки (для R6); число рабочих дней; согласующий | сервис отсутствий, календарь |
| Спрашивает | **даты** — если не названы или неоднозначны | M-3 |
| Никогда не спрашивает | причину, медицинские сведения, комментарий | M-14 |
| Подтверждение | карточка запроса; карточка отмены | M-4, M-5 |

     ├─ недоступен ─► повтор

## T-1. Только вопрос: «как оформить отгул?»

Ответ по `doc-timeoff-howto` (O-2) + предложение оформить.

```
👤 Алина: Как оформить отгул? Неудобно дёргать руководителя.
🤖 AI-buddy: Отгул оформляется запросом в сервисе отсутствий — его согласует руководитель, Ольга Миронова (демонстрационная инструкция).
   Писать ей отдельно не обязательно: запрос она увидит в сервисе. Наставника лучше предупредить самой.
   Правила демо-процесса: подать минимум за 1 рабочий день, до 5 рабочих дней подряд, не дальше 90 дней вперёд.
   Отправленный запрос — ещё не согласованный отгул.
   📄 Как оформить отгул (демо)
   Оформить сейчас?
   [Оформить отгул] [Нет, просто узнать]
```

- `[Оформить отгул]` → T-2.
- `[Нет, просто узнать]` → «Хорошо. Если понадобится — напиши» → конец T-E7.

## T-2. Даты

### Как агент понимает даты

| Фраза | Понимание (сегодня чт, 12.11) | Уточнение |
|---|---|---|
| «в пятницу» | пт, 13.11 | нет |
| «завтра» | пт, 13.11 | нет |
| «в понедельник» | пн, 16.11 | нет |
| «20-го», «20.11», «20 ноября» | пт, 20.11 | нет |
| «1-го» | вт, 01.12 (1 ноября прошло) | подтвердить: «Это вт, 1 декабря?» |
| «с 16 по 18», «пн–ср» | 16.11–18.11, 3 раб. дня | нет |
| «на три дня с понедельника» | 16.11–18.11 | нет |
| «пятница и понедельник» | 13.11–16.11, 2 раб. дня (выходные не считаются) | пояснить, что это один запрос |
| «в пятницу и в среду» | два несмежных дня | два запроса по очереди (M-13) |
| «на следующей неделе» | неделя 16–20.11 | В-2: какие дни |
| «на неделю» | 5 раб. дней, начало неизвестно | В-3: с какого дня |
| «в пятницу 20-го» при ближайшей пятнице 13-го | 20.11 — пятница; противоречия нет | нет |
| «в четверг 20-го» | 20.11 — пятница, противоречие | В-4 |
| «в декабре», «после праздников» | период без даты | В-1 с подсказкой |
| «сегодня», «вчера» | 12.11 / 11.11 | T-3: R2 / R1 |

Правило: распознанные даты агент **всегда повторяет** с днём недели и числом рабочих дней.

### Вопросы

**В-1. Даты не названы.**

```
🤖 AI-buddy: На какой день нужен отгул? Ближайшие доступные:
   [Пт, 13 ноября] [Пн, 16 ноября] [Вт, 17 ноября] [Другая дата] [Несколько дней]
```

- `[Другая дата]` → выбор даты в календаре (недоступные даты неактивны) или ввод текстом.
- `[Несколько дней]` → «С какого по какое число?» → выбор диапазона.

**В-2. «На следующей неделе».**

```
🤖 AI-buddy: Какие дни следующей недели?
   [Пн, 16] [Вт, 17] [Ср, 18] [Чт, 19] [Пт, 20] [Всю неделю — 5 дней]
```

Можно выбрать несколько подряд идущих. Если выбраны несмежные (пн и чт) → «Это два отдельных запроса. Оформим по очереди?» `[Да]` `[Выбрать заново]`.

**В-3. «На неделю».**

```
🤖 AI-buddy: С какого дня? Неделя — это 5 рабочих дней, больше в одном запросе нельзя.
   [С пн, 16 ноября] [С пн, 23 ноября] [Другой день]
```

**В-4. Противоречие.**

```
🤖 AI-buddy: 20 ноября — это пятница, а не четверг. Какой день нужен?
   [Чт, 19 ноября] [Пт, 20 ноября]
```

**«Не знаю пока»** на любой вопрос о датах:

```
🤖 AI-buddy: Хорошо, когда определишься с датой — просто напиши, оформим за минуту.
   Помни: подать нужно минимум за 1 рабочий день.
```

Ничего не создаётся. Конец T-E8.

## T-3. Проверки

Все нарушения показываются **сразу**, а не по одному.

| Нарушение | Ответ | Варианты |
|---|---|---|
| R1 прошлое | «11 ноября уже прошло — оформить отгул задним числом нельзя. Если ты отсутствовала, сообщи руководителю, Ольге Мироновой» | `[Выбрать другую дату]` |
| R2 сегодня | «На сегодня оформить нельзя: подать нужно минимум за 1 рабочий день. Если нужно отсутствовать сегодня, напиши руководителю — Ольге Мироновой» | `[Пт, 13 ноября]` `[Другая дата]` |
| R3 выходной в начале или конце | «14 ноября — суббота, отгул на выходной не нужен. Возможно, имелась в виду пятница или понедельник?» | `[Пт, 13]` `[Пн, 16]` |
| R3 праздник | «31 декабря в демо-календаре — праздник» | ближайшие рабочие дни |
| R4 больше 5 дней | «16–24 ноября — это 7 рабочих дней, а в одном запросе можно до 5. На больший срок договорись с руководителем» | `[16–20 ноября (5 дней)]` `[Другие даты]` |
| R5 дальше 90 дней | «15 марта — дальше, чем 90 дней. Сейчас можно оформить до 10 февраля включительно» | `[Другая дата]` |
| R6 пересечение | «На 13 ноября уже есть запрос ABS-2031 — „Согласован“» | `[Перенести его]` `[Другая дата]` `[Оставить как есть]` |
| R6 спорная попытка | «Прошлый запрос на эти даты ещё уточняется. Пока не выясним, новый оформить нельзя» | `[Проверить сейчас]` |
| R7 порядок дат | «Похоже, даты перепутаны: с 16 по 20 ноября?» | `[Да, 16–20]` `[Ввести заново]` |
| Сервис не ответил на проверку R6 | «Не могу проверить твои запросы — сервис отсутствий не отвечает. Попробуем через минуту?» Карточка не показывается | `[Попробовать ещё раз]` → конец T-E9 |

Разбивать срок больше 5 дней на несколько запросов агент **не предлагает**: это обход правила.

Диапазон с выходными внутри — допустим; выходные не считаются:

```
👤 Алина: отгул в пятницу и понедельник
🤖 AI-buddy: Это один запрос: пт, 13 — пн, 16 ноября, 2 рабочих дня (выходные не считаются).
```

Если на эти даты был **отклонённый** запрос — новый можно; агент показывает прошлую причину: «На эти даты запрос ABS-2025 отклонили: „Важный релиз в пятницу“. Возможно, стоит сначала обсудить с Ольгой Мироновой». `[Всё равно оформить]` `[Сначала поговорю]`.

## T-4. Карточка

```
┌─ Запрос на отгул ─────────────────────────────── v1 ─┐
│ Тип:           Отгул                                  │
│ Даты:          пт, 13 ноября 2026                     │
│                1 рабочий день                         │
│ Согласующий:   Ольга Миронова (руководитель)          │
│                                                       │
│ Запрос уйдёт руководителю. Отгул будет согласован     │
│ только после его решения. Причину указывать не нужно. │
│ ℹ️ Демонстрационный процесс                            │
│                                                       │
│ [Отправить]   [Изменить даты]   [Отмена]              │
└───────────────────────────────────────────────────────┘
```

| Поле | Редактируется |
|---|---|
| Тип | нет (в прототипе один тип) |
| Даты | да: в карточке или чатом («давай лучше понедельник») → R1–R7 заново → v2 |
| Согласующий | нет |

Правки:

| Стажёр пишет | Реакция |
|---|---|
| «Поменяй на понедельник» | v2: пн, 16.11 · 1 рабочий день |
| «Добавь ещё понедельник» | v2: пт 13 — пн 16 · 2 рабочих дня |
| «Добавь причину: к врачу» | «Причину указывать не нужно — её нет в запросе». Карточка не меняется (M-14) |
| «Сделай отпуск» | T-9, карточка не меняется |
| «Не надо» / `[Отмена]` | «Хорошо, запрос не отправляю» → конец T-E3 |

## T-5. Подтверждение и повторная проверка

M-5 + R1–R7 заново. Особые случаи:

| Ситуация | Ответ |
|---|---|
| Карточку показали в чт 23:50, подтвердили в пт 00:10 — дата стала «сегодня» | «Пятница уже наступила — на сегодня оформить нельзя. Выбрать другой день?» → новая версия |
| В другой вкладке создан запрос на те же даты | «На эти даты уже есть запрос ABS-2031» → R6 |
| Повторное нажатие | одна попытка (M-5) |
| Права изменились | M-10 |

## T-6. Отправка и исходы

Ожидание: «⏳ Отправляю запрос в сервис отсутствий…».

### Успех

```
🤖 AI-buddy: ✅ Запрос ABS-2031 отправлен · 12.11.2026, 15:40
   Отгул: пт, 13 ноября · 1 рабочий день.
   Статус: «Отправлен» — ждёт решения Ольги Мироновой. Это ещё не согласование.
   Наставника, Игоря Белова, предупреди сама — я ему не пишу.
   Напишу, когда руководитель примет решение.
   [Проверить статус] [Отменить запрос]
```

В плане, в блоке «Мои заявки и запросы»: «Отгул · 13.11 · Отправлен · ABS-2031 · 15:40». Сохраняется после обновления страницы.

### Отказ сервиса

| Код имитации | Что видит стажёр |
|---|---|
| `OVERLAP` | «Сервис сообщил, что на эти даты уже есть запрос» + номер, если вернул |
| `RULE_VIOLATION` | правило в формулировке имитации + выбор других дат |
| `VALIDATION_ERROR` | что исправить → карточка |
| `NOT_ALLOWED` | M-10 |

Конец T-E2. Ничего не меняется.

### Сервис недоступен / таймаут / сбой сохранения

Как в M-6, M-7. При таймауте новые запросы на **пересекающиеся** даты блокируются до сверки; на другие даты — можно.

```
🤖 AI-buddy: ⏳ Сервис отсутствий долго не отвечает. Результат уточняется.
   Не оформляй отгул на 13 ноября заново — я сам проверю, дошёл ли запрос, и напишу.
   [Проверить сейчас]
```

## T-7. После отправки

Статусы меняет ведущий через панель имитации; агент сообщает первым (M-8).

**На рассмотрении**

```
🤖 AI-buddy: 🔔 Руководитель открыл запрос ABS-2031 на отгул 13.11. Статус: «На рассмотрении».
```

**Согласован**

```
🤖 AI-buddy: 🔔 Отгул на пт, 13 ноября согласован — Ольга Миронова, 12.11, 17:05. Запрос ABS-2031.
   [Отменить отгул]
```

**Отклонён**

```
🤖 AI-buddy: 🔔 Запрос ABS-2031 на отгул 13.11 отклонён. Причина: «В пятницу важный релиз, давай перенесём».
   Можно выбрать другие даты или обсудить с Ольгой Мироновой.
   [Выбрать другие даты] [Понятно]
```

`[Выбрать другие даты]` → T-2 (В-1).

## T-8. Отмена и перенос

### Отмена — по M-9

Можно, пока не наступил первый день отгула: статусы «Отправлен», «На рассмотрении», «Согласован».

```
👤 Алина: отмени отгул в пятницу
🤖 AI-buddy:
┌─ Отмена запроса на отгул ───────────────────────────┐
│ Запрос ABS-2031 · пт, 13 ноября · Согласован         │
│ Отгул будет отменён, руководитель увидит отмену.     │
│ [Отменить отгул]   [Не отменять]                     │
└──────────────────────────────────────────────────────┘
👤 Алина: [Отменить отгул]
🤖 AI-buddy: ✅ Запрос ABS-2031 отменён · 12.11, 18:00. 13 ноября — обычный рабочий день.
```

| Ситуация | Ответ |
|---|---|
| Первый день наступил или прошёл | «Отгул уже начался — отменить через меня нельзя. Напиши руководителю, Ольге Мироновой» |
| Отклонён / уже отменён | «Этот запрос уже закрыт» |
| Результат уточняется | «Сначала выясним, создан ли запрос» `[Проверить сейчас]` |
| Несколько активных | «Какой отменить?» кнопками с датами |

### Перенос = отмена + новый запрос

```
👤 Алина: перенеси отгул с пятницы на понедельник
```

Порядок зависит от пересечения старых и новых дат:

| Случай | Порядок | Почему |
|---|---|---|
| Новые даты **не пересекаются** со старыми (13.11 → 16.11) | 1) карточка нового запроса → отправка; 2) после успеха — карточка отмены старого | если новый не пройдёт, старый отгул сохранится |
| Новые даты **пересекаются** со старыми (13–16.11 → 16–17.11) | 1) карточка отмены старого → отмена; 2) карточка нового | R6 не даст создать новый, пока старый активен |

```
🤖 AI-buddy: Перенос — это новый запрос и отмена старого. Сначала оформим отгул на пн, 16 ноября, потом отменим пятницу — так ты не останешься без отгула, если что-то пойдёт не так.
┌─ Запрос на отгул ── v1 ─┐ … пн, 16 ноября … └──┘
👤 Алина: [Отправить]
🤖 AI-buddy: ✅ Запрос ABS-2040 отправлен … Теперь отменим отгул на пятницу?
┌─ Отмена запроса на отгул ─┐ … ABS-2031 · пт, 13 ноября … └──┘
```

Если стажёр отказался от второй части («нет, пятницу оставь») — у него два запроса. Это допустимо: даты не пересекаются.

Если сервис подтвердил отказ создания — старый запрос не отменяется. При таймауте исход неизвестен: «Исход нового запроса уточняется; отгул на пятницу пока не отменяю». Второе действие заблокировано до сверки, отсутствие нового запроса не утверждается.

## T-9. Не отгул

| Запрос | Ответ |
|---|---|
| Отпуск | «Отпуск я не оформляю. С этим поможет куратор стажировки — Дарья Лебедева. Если нужен отгул на несколько дней (до 5) — оформлю» |
| Больничный | «Больничный я не оформляю, подробности о здоровье мне писать не нужно. Сообщи руководителю, Ольге Мироновой; по оформлению поможет куратор, Дарья Лебедева» |
| Полдня, «уйти пораньше», «опоздаю» | «Отгул оформляется только на целые дни. Про часть дня договорись с руководителем — Ольгой Мироновой» |
| Командировка | M-12 |

**В-6. Неясно: отгул или больничный.**

```
👤 Алина: заболела, завтра не выйду
🤖 AI-buddy: Выздоравливай! Подробности писать не нужно.
   Если нужен отгул на завтра (пт, 13 ноября) — могу оформить. Больничный я не оформляю: о нём сообщи руководителю, Ольге Мироновой.
   [Оформить отгул на 13 ноября] [Нет, сообщу руководителю]
```

Слово «заболела» не попадает ни в карточку, ни в сервис, ни в логи (M-14).

## T-10. Без LLM

Кнопка `[Оформить отгул]` → форма: выбор одной даты или диапазона в календаре (недоступные даты неактивны по R1–R5) → проверка R6 → та же карточка → M-5, M-6. Тексты шаблонные.

## Конечные состояния

| Код | Чем закончилось | Что сохранено |
|---|---|---|
| T-E1 | запрос отправлен (или найден при сверке) | номер, статус, даты, время, попытка |
| T-E2 | сервис отказал | попытка с отказом |
| T-E3 | карточка отменена или устарела | версии карточки; сервис не вызывался |

| T-E6 | не отгул или не для себя — направлен к человеку | ничего |

## Критерии приёмки (основа для OpenSpec)

1. WHEN дата не известна THEN карточка не создаётся.
2. WHEN стажёр подтверждает карточку и имитация возвращает номер THEN номер, даты, статус «Отправлен» и время видны в чате и плане после обновления страницы, а текст не содержит «согласован».
3. WHEN дата в прошлом, сегодня, выходной, больше 5 рабочих дней или дальше 90 дней THEN карточка не создаётся и показаны все причины.
4. WHEN на даты есть активный запрос THEN новый не создаётся.
5. WHEN агент ведёт диалог об отгуле THEN он не спрашивает причину, а сведения о здоровье из сообщения не попадают в карточку и запрос.
6. WHEN подтверждение повторено THEN создаётся один запрос.
7. WHEN вызов завершился таймаутом THEN показано «Результат уточняется», а запрос на пересекающиеся даты заблокирован до сверки.
8. WHEN имитация вернула «Согласован» THEN агент сообщает об этом первым, а статус меняется только по ответу имитации.
9. WHEN стажёр отменяет согласованный отгул до первого дня THEN после подтверждения статус — «Отменён».
10. WHEN первый день отгула наступил THEN отмена через агента недоступна.
11. WHEN перенос на непересекающиеся даты и новый запрос не создан THEN старый не отменяется.
12. WHEN LLM недоступна THEN отгул можно оформить через кнопочную форму с теми же проверками.
