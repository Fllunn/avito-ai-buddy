# Сценарий 2. Запрос доступа к рабочему ресурсу

> Общие механизмы — [00-common.md](00-common.md) (M-…). Демо-данные, каталог ресурсов и план — [M-0](00-common.md#m-0-демо-данные-на-которых-показаны-примеры).

## Проблема

В первые дни стажёр тратит много времени на доступы: не знает, какие нужны, где их запросить, кто согласует, и не понимает, дошла ли заявка. Наставник объясняет это каждому новичку. Сценарий доводит стажёра от «не могу открыть» до созданной заявки с номером и видимым статусом.

## Основание

- Чек-лист (общая вкладка, п. 5): «Запроси доступ в пространство своего кластера и/или команды» — 1-я неделя.
- Ответы организаторов: в Авито есть внутренний сервис заявок на доступ. Заявка может включать проект, обоснование и уровень прав (чтение, редактирование, администрирование). Согласующий зависит от типа ресурса: владелец, руководитель, DevOps или другой ответственный. Перед заявкой стажёр может свериться с наставником, нужен ли доступ. Процесс для прототипа моделируется самостоятельно.
- Ещё одно уточнение организаторов: стажёру выдают **те же доступы, что и остальным членам команды**. Данные по стратегии, финансам и планам запусков — если этого требуют задачи. Отсюда правила каталога: уровни как у члена команды, тип ресурса «по задаче» ([M-0](00-common.md#каталог-ресурсов-демо)).
- Доступы — первая по частоте тема организационных вопросов к наставнику ([ответы организаторов](../sources/organizers-qa.md)).
- Сервис заявок в прототипе — **имитация**. Её контракт (операции, поля, ошибки, ключ попытки) описывается в OpenSpec до реализации.

## Границы

- **Входит:** ресурсы из каталога; создание заявки; просмотр статуса; отмена открытой заявки; повторная подача после отказа; отметка P6 по ответу сервиса.
- **Не входит:** ресурсы вне каталога; уровни, которых нет у членов команды; отзыв выданного доступа; заявки за другого человека; техническая диагностика «почему не открывается»; уведомления согласующему.

## Статусы заявки (имитация)

| Статус | Значение | Шаг P6 (если ресурс — пространство своей команды) |
|---|---|---|
| Создана | сервис принял заявку | ожидает другого участника (согласующий) |
| На рассмотрении | согласующий открыл заявку | ожидает другого участника |
| Одобрена | согласовано, **доступ выдан** (в демо это одно событие) | выполнен; P7 становится доступен |
| Отклонена | согласующий отказал, есть причина | требует внимания |
| Отменена | стажёр отменил | не начат |
| Результат уточняется | исход вызова неизвестен (M-7) | последнее подтверждённое + «уточняется» |
| Нужна ручная проверка | сверка не дала ответа (M-7) | требует внимания |

Заявки на ресурсы, не связанные с шагом плана, видны в блоке «Мои заявки и запросы».

## Данные

| | Что | Как |
|---|---|---|
| Знает заранее | профиль (команда, роль), видимая часть каталога, рекомендованные ресурсы команды, контакты | M-1 |
| Получает сам | есть ли доступ; открытые заявки на ресурс; прошлые отказы и их причины; спорные попытки; согласующий; допустимые уровни и уровень по умолчанию | каталог, сервис заявок, хранилище попыток |
| Готовит сам | черновик обоснования | из плана и профиля |
| Спрашивает | **ресурс** — если не назван или неоднозначен | M-3 |
| | **уровень** — только если у ресурса больше одного уровня члена команды | M-3 |
| | **для чего нужен доступ** — если ресурс вне списка команды и вне плана (черновик не из чего составить) и **всегда** для ресурсов «по задаче» | M-3 |
| Не спрашивает | согласующего, проект, сроки, личные данные | — |
| Подтверждение | карточка заявки; карточка отмены | M-4, M-5 |

 └► A-11 Попытка → вызов → исход (M-6)

## A-1. Вход

### Что пишет стажёр

| Тип | Примеры | Что агент уже знает после фразы |
|---|---|---|
| Явный запрос с ресурсом | «Нужен доступ к PAY», «Запроси доступ в пространство команды» | ресурс (кандидат) |
| Явный запрос без ресурса | «Мне нужен доступ», «Как получить доступы?» | ничего |
| Проблема | «Не могу открыть пространство команды», «В трекере пишет „нет прав“», «Репозиторий не открывается» | ресурс (кандидат) + «возможно, доступа нет» |
| Только вопрос | «Как вообще запрашивают доступ?» | ответ по `doc-access-howto` (O-2) + «Оформить сейчас?» |
| Из плана | кнопка `[Запросить доступ]` у шага P6 | ресурс = пространство своей команды |
| Из ответа агента | кнопка `[Запросить доступ]` в O-1 / O-2 | ресурс из контекста ответа |

Фраза-проблема («не могу открыть») не значит, что нужна новая заявка: сначала A-4 — может, доступ уже есть или заявка уже на рассмотрении.

## A-2. Какой ресурс

### Как сопоставляется

1. Поиск **только по видимой** пользователю части каталога: название, синонимы («джира», «трекер», «вики», «конфлюенс», «репа», «графана», «мониторинг»), код проекта (PAY, SRCH).
2. «Пространство команды», «пространство моей команды» → пространство **своей** команды.
3. Одно совпадение → ресурс определён. Агент всё равно называет его полностью в следующем сообщении или карточке.
4. Несколько совпадений → вопрос с кнопками: сначала ресурсы своей команды, потом остальные, последняя — «Другое».
5. Ни одного → вопрос «Что именно не открывается?» + рекомендованные ресурсы команды кнопками. После второй неудачи — «не нашёл» + наставник.

### Вопросы

**В-1. Ресурс не назван.**

```
👤 Алина: Мне нужен доступ
🤖 AI-buddy: К чему нужен доступ? Вот что рекомендовано команде «Платежи»:
   [Пространство команды «Платежи»] [Проект PAY в трекере] [Репозиторий сервиса платежей] [Дашборды мониторинга] [Другое] [Не знаю]
```

**В-1, ответ «Не знаю».**

```
🤖 AI-buddy: Ничего страшного. На 1-й неделе по плану нужен доступ в пространство команды — с него и стоит начать.
   Остальные доступы обычно понадобятся под задачи — их лучше обсудить с наставником, Игорем Беловым.
   [Запросить пространство команды] [Спрошу наставника]
```

**В-1, ответ «Другое»** → «Напиши название или опиши, что хочешь открыть» → снова сопоставление.

**В-2. Неоднозначно.**

```
👤 Алина: дай доступ в джиру
🤖 AI-buddy: В трекере задач есть несколько проектов. Какой нужен?
   [PAY — команда «Платежи»] [SRCH — команда «Поиск»] [Другой]
```

**В-3. Не нашли.**

```
👤 Алина: нужен доступ в Мегаплан
🤖 AI-buddy: Не нашёл ресурса «Мегаплан» среди тех, к которым можно запросить доступ.
   Проверь название или выбери из списка. Если не уверена, что он нужен, спроси наставника — Игорь Белов.
   [Пространство команды «Платежи»] [Проект PAY в трекере] [Другое]
```

Скрытый ресурс (`salary-reports`) обрабатывается **так же**, как несуществующий: тот же текст, без намёка на существование (M-10).

## A-3. Можно ли стажёру запросить

Проверка на бэкенде: роль «стажёр» × ресурс → `can_request`.

```
👤 Алина: Запроси доступ к пространству инцидентов безопасности
🤖 AI-buddy: Запросить доступ к «Пространство инцидентов безопасности» стажёр не может.
   Если он нужен для задачи, обсуди это с наставником — Игорь Белов.
```

Карточка не создаётся, сервис не вызывается. Конец A-E6.

## A-4. Что уже есть по ресурсу

Агент получает это сам, до вопросов про уровень и обоснование.

| Состояние | Ответ | Дальше |
|---|---|---|
| Доступ уже есть | «У тебя уже есть доступ к X (чтение) — заявка ACC-0981 одобрена 04.11» | A-15 |
| Открытая заявка («Создана», «На рассмотрении») | статус, время, согласующий; новая заявка не создаётся | `[Проверить статус]` `[Отменить заявку]` → конец A-E5 |
| Спорная попытка («Результат уточняется», «Нужна ручная проверка») | M-7: новая заявка заблокирована | `[Проверить сейчас]` → конец A-E5 |
| Прошлая заявка отклонена | причина отказа + совет | A-14 |
| Прошлая заявка отменена | без комментариев | дальше |
| Ничего | — | A-5 |
| Сервис заявок не ответил на проверку | «Не могу проверить твои заявки — сервис не отвечает. Попробуем через минуту?» Карточку не показываем: без проверки дубля нельзя | `[Попробовать ещё раз]` → конец A-E9 |

```
👤 Алина: не могу открыть пространство команды
🤖 AI-buddy: По пространству «Платежей» у тебя уже есть заявка ACC-1042 — «На рассмотрении» с 12.11, 14:30.
   Согласующий: Ольга Миронова. Доступ появится после одобрения, новую заявку создавать не нужно.
   [Проверить статус] [Отменить заявку]
```

## A-5. Ресурс вне списка команды

Если ресурса нет среди рекомендованных команде стажёра, агент советует свериться с наставником, но не запрещает.

```
👤 Алина: нужен доступ в пространство команды «Поиск»
🤖 AI-buddy: «Пространство команды „Поиск“» не входит в рекомендованные доступы команды «Платежи».
   Перед заявкой лучше уточнить у наставника, Игоря Белова, нужен ли он для твоих задач.
   [Всё равно оформить] [Сначала спрошу наставника]
```

- `[Сначала спрошу наставника]` → «Хорошо. Когда решишь — просто напиши» → конец A-E8. Ничего не сохраняется.
- `[Всё равно оформить]` → A-6. В A-7 агент спросит, для чего нужен доступ (В-5).

### Ресурс «по задаче»

Стратегия, финансы, планы запусков. Такие данные стажёру выдают, только если их требуют задачи. В список команды они не входят никогда, поэтому A-5 срабатывает всегда, а обоснование — только ответ стажёра на вопрос В-5, без черновика агента.

```
👤 Алина: нужен доступ к планам запусков
🤖 AI-buddy: «Планы запусков кластера „Финтех“» выдают по конкретной задаче. Согласует руководитель — Ольга Миронова.
   Если доступ нужен для задачи, скорее всего, наставник, Игорь Белов, о ней знает — лучше сверься с ним.
   [Оформить для задачи] [Сначала спрошу наставника]
👤 Алина: [Оформить для задачи]
🤖 AI-buddy: Для какой задачи нужен доступ? Это увидит руководитель.
👤 Алина: PAY-31, оценить, как запуск нового способа оплаты повлияет на метрики
```

Дальше A-6 (у ресурса один уровень — вопроса нет) → карточка, в которой обоснование — переформулированный ответ стажёра. «Не знаю» на вопрос о задаче → «Тогда без задачи этот доступ не оформить — уточни у наставника» → конец A-E8.

## A-6. Уровень доступа

Допустимые уровни и уровень по умолчанию — из каталога: **такие же, как у члена команды** для этого ресурса. Отдельных ограничений для стажёра нет. «Администрирование» возможно, только если оно есть у членов команды (в демо-каталоге — ни у одного ресурса).

| Вариантов | Поведение |
|---|---|
| 1 | вопроса нет; уровень показан в карточке |
| 2+ | вопрос **В-4**, вариант по умолчанию первым |

**В-4.**

```
🤖 AI-buddy: Какой доступ к репозиторию сервиса платежей нужен?
   Для начала обычно хватает чтения. Запись — если наставник уже дал задачу с изменениями в коде.
   [Чтение (обычно)] [Запись] [Не знаю]
```

- «Не знаю» → берётся уровень по умолчанию с пояснением: «Поставлю „чтение“ — его хватит, чтобы изучить код. Если понадобится запись, оформим отдельно».
- Стажёр просит недопустимый уровень:

```
👤 Алина: дай мне админа на репозиторий
🤖 AI-buddy: У членов команды «Платежи» нет администрирования этого репозитория — его выдают только владельцу сервиса. Могу запросить чтение или запись.
   [Чтение] [Запись]
```

Уровень назван в исходной фразе («нужна запись в PAY») → вопроса нет, если уровень допустим.

## A-7. Обоснование

Обоснование видит согласующий. Агент составляет черновик сам:

| Случай | Черновик |
|---|---|
| ресурс — шаг плана (P6) | «Стажёр команды „Платежи“ (Backend). Доступ нужен для шага адаптации 1-й недели „Запросить доступ в пространство команды“.» |
| ресурс рекомендован команде | «Стажёр команды „Платежи“ (Backend). Ресурс рекомендован команде для работы стажёра.» |
| ресурс вне списка команды | черновика нет → вопрос **В-5** |
| ресурс «по задаче» | черновика нет → вопрос **В-5** о конкретной задаче |

**В-5.**

```
🤖 AI-buddy: Коротко напиши, для чего нужен доступ к «Пространство команды „Поиск“». Это увидит согласующий.
👤 Алина: Наставник попросил посмотреть, как «Поиск» описывает API для платежей
```

Агент переформулирует ответ в обоснование («Стажёр команды „Платежи“. Нужно изучить описание API команды „Поиск“ по задаче от наставника») и показывает в карточке. Стажёр может изменить текст.

Правила обоснования: не пустое, 10–500 символов, без личных данных. Слишком короткий ответ («надо») → «Напиши чуть подробнее, для какой задачи — иначе согласующий может отказать». Второй раз «не знаю» → «Тогда лучше сначала уточнить у наставника» → конец A-E8.

## A-8. Карточка заявки

```
┌─ Заявка на доступ ────────────────────────────── v1 ─┐
│ Ресурс:        Пространство команды «Платежи»         │
│ Уровень:       Чтение                                 │
│ Согласующий:   Ольга Миронова (руководитель команды)  │
│ Обоснование:   Стажёр команды «Платежи» (Backend).    │
│                Доступ нужен для шага адаптации        │
│                1-й недели «Запросить доступ           │
│                в пространство команды».      [✎]      │
│                                                       │
│ После отправки заявка уйдёт согласующему.             │
│ Доступ появится только после одобрения.               │
│ ℹ️ Демонстрационный процесс                            │
│                                                       │
│ [Отправить]   [Изменить]   [Отмена]                   │
└───────────────────────────────────────────────────────┘
```

| Поле | Редактируется | Как |
|---|---|---|
| Ресурс | да, через «Изменить» или чат | выбор из видимого каталога → A-3…A-7 заново |
| Уровень | да, если вариантов больше одного | выбор из допустимых |
| Согласующий | нет | подставляется из каталога |
| Обоснование | да | текст в карточке или чат |

## A-9. Правки

| Что пишет стажёр | Реакция |
|---|---|
| «Давай запись вместо чтения» | v2 с новым уровнем, если он допустим: «Поменял уровень на „Запись“. Проверь и отправь» |
| «Допиши в обоснование, что это для задачи PAY-12» | v2 с дополненным текстом |
| «Нет, мне нужен репозиторий, а не пространство» | новый ресурс → A-3…A-7 → новая карточка v1 (старая заменена) |
| «Сделай админа» | если у членов команды такого уровня нет — отказ по A-6, карточка не меняется |
| Правка поля в карточке | v2; кнопка «Отправить» у v1 неактивна |
| «Не надо» / `[Отмена]` | карточка отменена: «Хорошо, заявку не отправляю» → конец A-E3 |

---

## A-10. Подтверждение и повторная проверка

Нажатие `[Отправить]` или «да, отправляй». Порядок проверок — M-5. Особенности сценария:

| Что изменилось после показа карточки | Ответ |
|---|---|
| Ресурс стал невидимым или запрещённым | «Эта заявка больше недоступна. Ничего не отправлено» — без деталей |
| Уровень больше не допустим | «Уровень „Запись“ больше недоступен. Отправить с уровнем „Чтение“?» → новая версия |
| В другой вкладке уже создана заявка на этот ресурс | «Заявка на этот ресурс уже создана — ACC-1042, „Создана“». Новая не создаётся |
| Двойной клик / повтор той же версии | показывается текущая попытка, вторая не создаётся |
| Карточка устарела (24 ч) | «Черновик устарел. Создать заново?» → данные перепроверяются |

## A-11. Отправка и исходы

Ожидание: «⏳ Отправляю заявку в сервис заявок…». Исходы — M-6.

### Успех

```
🤖 AI-buddy: ✅ Заявка ACC-1042 создана · 12.11.2026, 14:05
   Ресурс: Пространство команды «Платежи», чтение.
   Статус: «Создана». Согласующий: Ольга Миронова.
   Доступ появится после одобрения — я напишу, когда статус изменится.
   Пока можно завести конспект встреч с наставником — это следующий шаг в плане.
   [Проверить статус] [Отменить заявку]
```

План: P6 → «ожидает другого участника · согласующий Ольга Миронова · сервис заявок, ACC-1042, 14:05». Номер, статус и время видны после обновления страницы.

### Отказ сервиса

Имитация может отказать, даже если проверки бэкенда прошли (гонка, правило имитации).

| Код имитации | Что видит стажёр |
|---|---|
| `DUPLICATE_OPEN_REQUEST` | «Сервис сообщил, что заявка на этот ресурс уже есть» + её номер и статус, если сервис его вернул |
| `ALREADY_GRANTED` | «Сервис сообщил, что доступ уже выдан» → A-15 |
| `LEVEL_NOT_ALLOWED` | «Этот уровень для ресурса недоступен» + допустимые уровни → новая карточка |
| `VALIDATION_ERROR` | конкретное поле и что исправить → карточка с правкой |
| `NOT_ALLOWED` | M-10, без деталей |

Шаг плана не меняется. Конец A-E2.

### Сервис явно недоступен

```
🤖 AI-buddy: Сервис заявок сейчас недоступен — заявка не создана.
   [Отправить ещё раз] [Позже]
```

`[Отправить ещё раз]` — та же версия карточки, повторная проверка M-5, тот же ключ попытки.

### Таймаут или сбой сохранения

M-6 / M-7: «Результат уточняется», повтор по ресурсу закрыт, автоматическая сверка, кнопка `[Проверить сейчас]`. Возможные концы: A-E1 (нашлась), «заявка не была создана» → `[Отправить заново]`, A-E9 (ручная проверка).

## A-12. После отправки

Статус меняет ведущий демо через панель имитации (M-8). Агент узнаёт об этом при открытии интерфейса или по запросу и пишет первым.

**На рассмотрении**

```
🤖 AI-buddy: 🔔 Заявку ACC-1042 взяли на рассмотрение · 12.11, 14:30. Согласующий: Ольга Миронова.
```

**Одобрена**

```
🤖 AI-buddy: 🔔 Заявка ACC-1042 одобрена — доступ к «Пространство команды „Платежи“» выдан (чтение).
   Шаг «Запросить доступ в пространство команды» выполнен. Следующий — «Изучить пространство команды».
   [Открыть шаг] [С чего начать?]
```

План: P6 → выполнен (источник: сервис заявок, ACC-1042, время); P7 → не начат, доступен.

**Отклонена**

```
🤖 AI-buddy: 🔔 Заявку ACC-1042 отклонили · 12.11, 16:10.
   Причина: «Укажите, для какой задачи нужен доступ».
   Можно подать новую заявку с другим обоснованием или уточнить у Ольги Мироновой.
   [Подать заново] [Показать заявку]
```

План: P6 → требует внимания (источник: отказ ACC-1042). Причина показывается в том виде, в каком её вернула имитация.

## A-13. Отмена заявки

По M-9. Отменить можно только заявки «Создана» и «На рассмотрении».

```
👤 Алина: отмени заявку на репозиторий, наставник сказал не нужно
🤖 AI-buddy:
┌─ Отмена заявки ──────────────────────────────────────┐
│ Заявка ACC-1047 · Репозиторий сервиса платежей · чтение │
│ Статус сейчас: «Создана»                              │
│ После отмены согласующий не будет её рассматривать.  │
│ [Отменить заявку]   [Не отменять]                    │
└───────────────────────────────────────────────────────┘
👤 Алина: [Отменить заявку]
🤖 AI-buddy: ✅ Заявка ACC-1047 отменена · 12.11, 15:02.
```

| Ситуация | Ответ |
|---|---|
| Заявку успели одобрить | «Заявку уже одобрили — доступ выдан, отменить нельзя. Отзыв доступа в AI-buddy не оформляется — обратись к согласующему» |
| Заявка отклонена или отменена | «Эта заявка уже закрыта (Отклонена 12.11)» |
| Результат уточняется | «Сначала нужно выяснить, создана ли заявка» + `[Проверить сейчас]` |
| Открытых заявок несколько, неясно какую | «Какую заявку отменить?» кнопками |
| Отмена для P6 | P6 → не начат |

## A-14. Повторная подача после отказа

Если последняя заявка на ресурс отклонена, новую подать можно, но агент сначала показывает прошлую причину.

```
👤 Алина: подай заново доступ в пространство
🤖 AI-buddy: Прошлую заявку ACC-1042 отклонили: «Укажите, для какой задачи нужен доступ».
   Лучше сначала поговорить с Ольгой Мироновой или наставником Игорем Беловым — иначе новую заявку могут отклонить по той же причине.
   Если готова подать сейчас — напиши, для какой задачи нужен доступ.
   [Подать с новым обоснованием] [Сначала поговорю]
```

- `[Подать с новым обоснованием]` → В-5 → карточка. Обоснование должно отличаться от отклонённого. Если текст совпадает: «Обоснование такое же, как в отклонённой заявке. Точно отправить так?» `[Изменить]` `[Отправить как есть]`.
- `[Сначала поговорю]` → конец A-E8.

## A-15. Доступ есть, но ресурс не открывается

```
👤 Максим: у меня не открывается пространство «Поиска»
🤖 AI-buddy: По данным сервиса заявок, доступ к «Пространство команды „Поиск“» у тебя есть: чтение, заявка ACC-0981 одобрена 04.11.
   Новая заявка не нужна. Если пространство всё равно не открывается, проблема не в заявке — напиши согласующему, Анне Петровой, или наставнику, Сергею Киму.
   Если нужен не просмотр, а редактирование — могу оформить заявку на этот уровень.
   [Запросить редактирование] [Понятно]
```

Агент не придумывает технические инструкции (перезайти, очистить кэш), если их нет в разрешённых материалах.

## A-16. Без LLM: кнопочная форма

Кнопка `[Запросить доступ]` в плане или в шаблонном сообщении M-11 открывает форму без LLM:

1. Ресурс — список видимого каталога (рекомендованные команде — сверху).
2. A-3, A-4, A-5 — те же проверки кодом, тексты шаблонные.
3. Уровень — список допустимых, по умолчанию выбран.
4. Обоснование — шаблонный черновик; для ресурса вне списка команды — пустое обязательное поле.
5. Та же карточка, те же M-5 и M-6.

🤖 AI-buddy: Дописал. Проверь новую версию:

## Конечные состояния

| Код | Чем закончилось | Что сохранено |
|---|---|---|
| A-E1 | заявка создана (или найдена при сверке) | номер, статус, время, попытка; P6 обновлён |
| A-E2 | сервис отказал | попытка с отказом; P6 без изменений |
| A-E3 | стажёр отменил карточку или она устарела | версии карточки; сервис не вызывался |
| A-E4 | доступ уже есть, заявка не нужна | ничего нового |
| A-E5 | открытая или спорная заявка уже есть | ничего нового |
| A-E6 | нет права запрашивать | ничего нового |
| A-E7 | ресурс не найден или скрыт | ничего нового |
| A-E8 | стажёр решил сначала поговорить с человеком | ничего нового |
| A-E9 | исход или состояние неизвестны, нужна ручная проверка или повтор позже | попытка в статусе «нужна ручная проверка» или ничего |

## Критерии приёмки (основа для OpenSpec)

1. WHEN стажёр подтверждает карточку и имитация возвращает номер THEN номер, статус и время сохранены и видны после обновления страницы, а P6 — «ожидает другого участника».
2. WHEN заявка «Создана» THEN ни чат, ни план не говорят, что доступ выдан.
3. WHEN ресурс скрыт THEN ответ совпадает с ответом для несуществующего ресурса, а в контекст LLM ресурс не попадает.
4. WHEN ресурс запрещён роли THEN карточка не показывается и сервис не вызывается.
5. WHEN по ресурсу есть открытая заявка THEN новая не создаётся, показывается существующая.
6. WHEN стажёр отменяет карточку THEN сервис не вызывается и план не меняется.
7. WHEN карточка изменена после показа THEN подтверждение старой версии отклоняется.
8. WHEN подтверждение отправлено дважды THEN создаётся одна заявка.
9. WHEN права изменились между показом и подтверждением THEN сервис не вызывается.
10. WHEN вызов завершился таймаутом THEN показано «Результат уточняется», новая заявка на тот же ресурс заблокирована до сверки.
11. WHEN имитация вернула «Одобрена» THEN P6 выполнен с источником «сервис заявок», P7 доступен, агент сообщил об этом первым.
12. WHEN имитация вернула «Отклонена» THEN показана причина, P6 — «требует внимания».
13. WHEN стажёр просит уровень, которого нет у членов команды для этого ресурса, THEN он не предлагается и не отправляется.
14. WHEN LLM недоступна THEN заявку можно оформить через кнопочную форму с теми же проверками.
15. WHEN ресурс относится к типу «по задаче» THEN агент спрашивает, для какой задачи нужен доступ, и советует свериться с наставником до карточки.
