# Критерии оценки

Каждый критерий оценивается экспертами по шкале **0–5**:
0 — не выполнен / не представлен; 1 — отдельные элементы, но практически не выполнен; 2 — в небольшой степени, существенные пробелы; 3 — частично, заметные недочёты; 4 — в основном, недочёты несущественны; 5 — полно и качественно.

**Итог = 40% онлайн-этап + 60% финальная защита.**

## 1. Допуск — 0 баллов и снятие с оценки, если:
- прототип **не запускается по инструкции** или эксперт не может пройти заявленный основной сценарий;
- **нет исходного кода или инструкций**, без которых невозможно запустить и проверить решение;
- в сдаче **нет продуктовой презентации**.

Отдельные ошибки, недочёты документации и отсутствие видео при работающем прототипе учитываются в критериях, но не снимают с оценки.

## 2. Онлайн-этап (40% итога)
| Вес | Критерий | Что это значит для нас |
|---|---|---|
| **30%** | Внедряемость и интеграции | совместимость со стеком Авито, интеграции через MCP-стиль, имитации как настоящие сервисы, лёгкая замена моков на реальные API |
| **25%** | Пользовательский опыт | понятный чат и панель онбординга, отзывчивость < 1 с, статусы ожидания, обработка сбоев |
| **20%** | Работоспособность сценариев | все заявленные сценарии проходят от запроса до результата |
| **15%** | Техническая реализация | качество кода, тесты, покрытие > 80%, SDD-спеки |
| 5% | Безопасность и данные | права пользователя, синтетические данные, нет секретов в репо |
| 5% | Продуктовая презентация | |

## 3. Финал (60% итога)
| Вес | Критерий |
|---|---|
| 20% | Ценность для стажёра и команды |
| **25%** | Качество живой демонстрации |
| 20% | Обоснованность технических решений (→ ADR в `docs/adr/`) |
| **25%** | Внедряемость и развитие |
| 5% | Качество защиты и ответов |
| 5% | Командное владение решением (каждый участник понимает систему) |
