# Кейс: AI-buddy — ИИ-наставник для стажёров

Выжимка кейса хакатона Hack&Change 2026 (Avito Start, автор кейса — Changellenge). Источник — PDF кейса, выданный организаторами.

## Задача
Создать прототип **AI-buddy** — ИИ-помощника, который помогает стажёру освоиться в новой команде: разобраться в процессах и инструментах, получить ответы на рабочие вопросы, пройти выбранные этапы адаптации и выполнить необходимые действия через корпоративные сервисы.

## Бизнес-контекст
- Адаптация стажёра: знакомство с командой → рабочие инструменты → первые задачи. Руководитель и наставник помогают войти в процессы, чек-лист задаёт основные шаги. У каждой команды свои инструменты, правила и ожидания.
- Проблема новичка: инструкции, договорённости и сведения о доступах разбросаны по разным сервисам; непонятно, что относится к его задачам, какой шаг следующий и к кому идти с вопросом.
- Пример: стажёру нужен отгул, он не знает порядка оформления и не уверен, стоит ли отвлекать руководителя. AI-buddy объясняет процедуру, помогает подготовить запрос через корпоративный сервис и показывает результат — не заменяя личного общения с наставником.
- Нагрузка на наставника: **40–48 ч** за 6-месячную программу, **55–65 ч** за 9-месячную (1:1, работа с куратором, обучение, ревью компетенций, обратная связь, экватор, выпускной).
- **AI-buddy должен сокращать рутинные обращения и организационные действия, а не заменять содержательную работу наставника.**

## Целевая аудитория
| Роль | Типичная задача |
|---|---|
| **Стажёр** (основной пользователь) | разобраться в задачах первых недель, найти инструкции, получить доступы, понять следующие шаги |
| Наставник (buddy) | познакомить с инструментами и процессами, помочь с первыми задачами, ответить на вопросы |
| Руководитель команды | определить ожидания, согласовать цели адаптации, контролировать важные шаги |
| HR BP | участвует в адаптации (можно предложить доп. сценарии) |

## Постановка (что сделать)
Сосредоточиться на **3–5 сценариях** адаптации либо на одном глубоко проработанном:
1. Описать путь стажёра в первые недели и выбрать сценарии (чек-лист Авито, собственный опыт, ожидания).
2. Научить помощника отвечать на вопросы о команде и инструментах с учётом контекста.
3. Реализовать все выбранные сценарии, **хотя бы в одном — действие через корпоративный сервис** или его имитацию.
4. Показать этапы адаптации, статусы задач и следующие шаги стажёра.
5. Обосновать архитектуру, работу с правами и подключение корпоративных сервисов.
6. Предложить метрики пользы и способ проверить эффект на стажёрах.

Количество сценариев на оценку не влияет — важно реализовать весь заявленный функционал. При одном сценарии достаточно показать его этапы, статус и следующие шаги, не строя систему управления всем онбордингом.

**Действие считается выполненным**, если сервис или его имитация возвращает результат, который помощник отображает и сохраняет.

## Пространство решений
- Интерфейс — на выбор команды (чат, веб-сервис, расширение…).
- Корпоративные сервисы Авито: отсутствия, командировки, найм, увольнения, согласия, бенефиты, чек-лист новичка.
- У Авито уже есть: данные сотрудников, авторизация, ролевая модель, аналитика событий, инструменты настройки ИИ-агентов (промпты, MCP), внутренний ИИ-крон, feature flags (compile-time и runtime). Для прототипа их API можно имитировать и оформлять действия через MCP, не создавая системы заново.
- Стек Авито: Go (Python + Flask — в отдельных случаях), PostgreSQL, Redis; React, TypeScript, TanStack, Zustand, Zod. **Оценивается совместимость архитектуры со стеком**, а не использование всех технологий.
- AI-сценарии — через **SDD** (spec-kit / OpenSpec), продвинутые промпты, скиллы, MCP.
- Инфраструктура Авито: Docker, Grafana, Clickstream, RPC/Apache Kafka, CI/CD. При отдельном размещении статического интерфейса нужен явный API-клиент.

## Ограничения
1. Основная аудитория — стажёры; отдельные интерфейсы для наставника/руководителя не обязательны.
2. Только синтетические или обезличенные данные, тестовые инструкции и имитации сервисов.
3. Тестовые инструкции не выдавать за регламенты Авито.
4. Реальные данные сотрудников и собственные аналоги HR-систем не нужны — авторизация и роли уже существуют.
5. AI-buddy учитывает права пользователя: недоступные сведения и операции не раскрываются и не выполняются.
6. Сценарии с чувствительными ПДн и финансовыми операциями — вне области задачи.
7. **Покрытие строк прикладного кода автотестами > 80%** (без зависимостей, сгенерированного кода и самих тестов).
8. Приложить воспроизводимый отчёт о покрытии и SDD-спецификации, по которым велась разработка AI-функций.
9. Простые локальные операции — **< 1 с**.
10. Обращения к LLM и внешним сервисам не блокируют интерфейс: статус ожидания, корректная обработка сбоя.

## Формат сдачи
На платформу — PDF-презентация со ссылкой на репозиторий **или** ZIP с кодом и презентацией. Приватный репозиторий — дать доступ аккаунту жюри **`hack-and-change-2026`**.

| # | Что | Требования |
|---|---|---|
| 1 | Прототип | работающий, с интерфейсом и реализацией всех заявленных сценариев |
| 2 | Код и документация | исходный код; README с инструкцией запуска (Docker или другой способ), версиями зависимостей, тестовыми учётными данными, порядком проверки и запуском тестов; SDD-спецификации; тесты и отчёт о покрытии |
| 3 | Тестовые данные | тестовые данные и имитации интеграций для воспроизведения сценариев |
| 4 | Видео | файл в ZIP/репозитории или ссылка на первом слайде / в README; **показать путь от запроса до результата** |
| 5 | Презентация | продуктовая, PDF |

Внешние API: указать сервис, модель, переменную окружения и подключение ключа; приложить пример конфигурации без секретов; для Docker — файлы запуска. Организаторы могут использовать свой ключ.

После дедлайна версия фиксируется → эксперты оценивают дистанционно → команда защищает тот же проект на финале. Дополнительные онлайн-сабмиты не требуются.
