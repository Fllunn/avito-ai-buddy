# 0013. CI на GitHub Actions

- **Статус:** принято
- **Дата:** 2026-11-15

## Контекст
Тесты и порог покрытия (> 80% по каждому модулю и в сумме) проверялись только вручную командой `make coverage`. Слияние в `master` идёт через PR, но PR не проверялся автоматически: сломанный тест или упавшее покрытие можно было заметить уже после слияния. Кейс требует воспроизводимый отчёт о покрытии, жюри оценивает внедряемость и качество кода.

## Решение
Workflow `.github/workflows/ci.yml` запускается на каждый PR, push в `master` и вручную. Два независимых job на `ubuntu-24.04`:

1. **Lint** — `gofmt -l` и `go vet` для `backend`, `mocks`, `scripts/coverage`; `tsc --noEmit` для frontend. Новых зависимостей нет: только штатные инструменты Go и TypeScript.
2. **Tests and coverage** — тот же `make coverage`, что и локально. Скрипт сам поднимает изолированные PostgreSQL 16.6 и Redis 7.4.1 через `docker compose` (`infra/test.compose.yaml`), гоняет Go-тесты с `-race`, Vitest и считает общий отчёт. Покрытие ≤ 80% валит job. Каталоги `coverage/` и `frontend/coverage/` сохраняются артефактом на 14 дней.

Версии Go и Node берутся из `backend/go.mod` и `frontend/.node-version`, то есть из того же источника, что и для локальной разработки. Реальная LLM не вызывается, секреты в CI не нужны.

## Альтернативы
- **Только `make test` без хранилищ.** Отклонено: интеграционные Go-тесты пропускаются без тестовых URL, порог покрытия не проверяется.
- **Service containers GitHub вместо `docker compose`.** Отклонено: контейнеры стартуют до checkout и не видят скрипт создания БД и ролей; появились бы две разные конфигурации тестового окружения.
- **golangci-lint, ESLint.** Отложено: новые зависимости и правила, которые пришлось бы согласовывать. Штатных `gofmt`/`go vet`/`tsc` достаточно для прототипа.
- **Автодеплой на демо-стенд.** Отложено: нужны SSH-секреты в GitHub; деплой пока выполняется вручную по [docs/deployment.md](../deployment.md).
- **`make infra-check` в CI.** Отложено: поднимает весь стек и долго идёт; изоляцию БД уже проверяют интеграционные тесты.

## Последствия
- PR с упавшим тестом, неформатированным Go-кодом или покрытием ≤ 80% виден сразу в GitHub.
- Локальный и CI-прогон совпадают: одна команда `make coverage`.
- Прогон покрытия занимает несколько минут из-за `-race` и Docker.
- Чтобы CI блокировал слияние, человек должен включить обязательные проверки для `master` в настройках репозитория (branch protection).
