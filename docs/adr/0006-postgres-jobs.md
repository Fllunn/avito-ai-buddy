# 0006. Устойчивые попытки и очередь PostgreSQL

- **Статус:** принято
- **Дата:** 2026-11-13

## Контекст

Подтверждение, сбой ответа и перезапуск не должны создавать повторное действие.

Основание: утверждённый [design.md](../../openspec/changes/build-onboarding-prototype/design.md), change `build-onboarding-prototype`.

## Решение

PostgreSQL — источник истины. Карточка, попытка с неизменяемым снимком, конфликтная резервация и job записываются транзакционно до HTTP-вызова. Worker использует lease; после возможной отправки сверяет прежний operation_key. Имитации атомарно сохраняют ключ и результат; not_created закрывает ключ для поздних вызовов. Результат, проекция плана, сообщение и событие сохраняются одной транзакцией. Более старые версии не откатывают проекцию. Redis служит только кэшем разрешённых справочников, отказ кэша допускает чтение источника.

## Альтернативы

Очередь Redis требует дополнительных гарантий доставки; вызов сервиса в HTTP-транзакции не переживает потерю ответа.

## Последствия

Неизвестный исход блокирует конфликтующие действия до сверки. Нужны тесты конкуренции и восстановления; распределённой транзакции с сервисом нет.
