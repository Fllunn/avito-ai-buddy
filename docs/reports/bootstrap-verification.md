# Проверка первого этапа, 13.11.2026

Область: задачи 1.1–1.4 `build-onboarding-prototype`. Это приёмка каркаса и инфраструктуры, не трёх бизнес-сценариев.

## Среда и команды

Локальный macOS ARM64, Go 1.27.0, Node 24.22.0, Docker Engine 28.3.3. В Linux-сборке frontend — Node 24.22.0, npm 11.19.1. Образы и прямые зависимости закреплены в Dockerfile, compose.yaml и package.json; транзитивные npm-зависимости — lockfile.

| Проверка | Результат |
|---|---|
| `make test` | Go с race detector и 2 Vitest/RTL-теста прошли; реальных LLM/сервисов нет |
| `make build` | оба Go-процесса и React/TypeScript frontend собраны |
| `make coverage-backend-native` | 100% операторов платформенных пакетов; это не общий отчёт строк |
| `cd frontend && npm run coverage` | 100% строк текущего каркаса, все прикладные исходники включены, entrypoint исключён |
| Docker build / `npm ci` | чистая Linux-установка по lockfile прошла; несоответствие optional-зависимостей macOS исправлено генерацией lockfile в целевом окружении |
| `make infra-check` | чистый запуск, health checks, изоляция БД, stop/up и down/up без потери контрольных данных прошли |
| Браузер `http://localhost:5173` | стартовый экран отрисован, кириллица и иконки видны, действия отключены с объяснением |

Тест инфраструктуры не публикует порты, использует только проект `ai-buddy-infra-check` и удаляет его тома после проверки. Основной проект `ai-buddy` оставлен работающим; его PostgreSQL/Redis-тома не удаляются.

## Ограничения

- Личный вход, история, план и действия ещё не реализованы. `/readyz` возвращает 503, даже если инфраструктурный процессный health check успешен.
- Начальная страница использует переданные исходники Figma Make; переписка и таймеры прототипа не импортированы как бизнес-логика.
- Прикладных тестов имитаций пока нет: их точка запуска использует общий платформенный код. Общий взвешенный line coverage трёх модулей — следующая задача 1.5.
- Реальная модель и провайдер не выбраны. Никакой результат fake не заявляется ответом настоящей модели.
