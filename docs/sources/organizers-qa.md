# Ответы организаторов по кейсу

> Источник: тема «Вопросы по кейсу» в чате трека Авито Hack&Change 2026 и рассылка организаторов. Снято: 2026-11-12.
> Здесь — только ответы организаторов, своими словами. Имена участников, задавших вопросы, не приводятся.

## Метрики онбординга стажёров (приблизительно)

| Показатель | Значение | Комментарий организаторов |
|---|---|---|
| Время до первой самостоятельной задачи | ~2 недели | данных нет, очень индивидуально, зависит от направления |
| Длительность адаптации | ~2 месяца | |
| Удовлетворённость онбордингом | 9/10 | |
| Удовлетворённость чек-листом | 68% | |
| Удовлетворённость наставником | 90% | |

## Нагрузка на наставника

| Период | Время наставника | Темы |
|---|---|---|
| Первые 2–3 месяца | ~5 ч/нед | доступы, задачи, погружение, 1:1 |
| После адаптации | ~2–3 ч/нед | 1:1, ревью задач, развитие |

Общая оценка из кейса: 40–48 ч за 6-месячную программу и 55–65 ч за 9-месячную (1:1, работа с куратором, обучение, ревью компетенций, обратная связь, экватор, выпускной). Более подробной разбивки нет.

## Самые частые вопросы стажёров к наставнику

1. Организационные: доступы, оборудование, документы.
2. По задачам: формулировка, ревью, приоритизация.
3. Профессиональные: инструменты, технологии.
4. Развитие: ИПР, матрица компетенций.
5. Обратная связь.

## Доступы

- Стажёрам выдают **те же доступы, что и остальным членам команды**: бэклоги и тикеты в трекере, пространства с техническими спецификациями и гайдами, дашборды продуктовых метрик, репозитории и код сервисов своей команды.
- Данные по стратегии, финансовым показателям и планам запусков тоже могут быть доступны, **если этого требуют задачи**.
- Заявки на доступ подают в трекере задач или во внутреннем сервисе; прямые ссылки на формы заявок есть в чек-листе. Дополнительный доступ оформляется так же.
- Перед заявкой стажёр может свериться с наставником, нужен ли ему этот доступ.
- В заявке, в зависимости от ресурса: проект, обоснование, уровень прав (чтение, редактирование, администрирование). Согласует, в зависимости от типа ресурса, владелец проекта, руководитель, DevOps или другой ответственный.
- Единой схемы заявок и полного списка статусов не дадут. Для прототипа процесс моделируется самостоятельно: создание заявки, статус, результат согласования.

## Корпоративные сервисы и инфраструктура

- Есть внутренние сервисы для отсутствий, командировок, найма, увольнений, согласий и бенефитов, а также сервис заявок на доступ.
- Есть инструменты настройки ИИ-агентов (промпты, MCP), внутренний ИИ-крон и feature flags. Для прототипа их API можно имитировать и оформлять действия через MCP. Подробностей о запуске агентов по событиям и списке MCP-инструментов не дадут.
- Интеграции с реальными системами не нужны: достаточно имитаций.

## Цели и прогресс

- На 1-й неделе стажёр обсуждает с руководителем цели, план адаптации, критерии успешной стажировки и OKR команды. Руководитель задаёт ожидания, согласует цели и контролирует основные шаги.
- Инструмент отслеживания прогресса (2-я неделя): стажёр вносит туда цели, задачи и ожидания. Конкретный формат организаторы уточняют.

## Приоритеты продукта

- Удобство стажёра и снижение нагрузки на наставника одинаково важны. Можно сделать акцент на одной цели или закрыть обе.

## Интерфейс и стек

- Канал взаимодействия любой; веб-чата достаточно, мессенджер преимуществ не даёт.
- Backend не обязательно на Go: стек любой, главное — работающее решение по требованиям кейса.
- Можно использовать фирменную палитру Авито; брендбук не дают — ориентир на вид Avito Start на сайте.

## LLM и сдача

- Внешние LLM через API разрешены. Ключи для разработки не выдают; для проверки организаторы подставят свой ключ. Фиксированного провайдера нет — в README указать сервис, модель, переменную окружения и пример конфигурации.
- Свои ключи передавать нельзя, даже в зашифрованном виде.
- Допустим тестовый режим без внешнего ключа, но в README нужно подробно описать подключение реальной LLM.
- Локальная модель не меняет состав сдачи: README должен объяснять, как её запустить и подключить; веса можно приложить.
- Покрытие тестами считается по всему прикладному коду, включая веб-интерфейс.
- Шаги чек-листа можно брать основой для тестового чек-листа с пометкой «тестовые данные».
- Сдача — в личном кабинете платформы; до дедлайна можно обновлять, проверяется последняя версия. Финальная защита — перед экспертами Авито.

## Что это значит для AI-buddy

- **Сценарий доступа** закрывает самую частую тему организационных вопросов. Уровни доступа стажёра — как у члена команды; данные «по задаче» запрашиваются с объяснением задачи ([02-access-request.md](../scenarios/02-access-request.md)).
- **Базовая линия для метрик** — 5 ч/нед наставника в первые 2–3 месяца, ~2 недели до первой самостоятельной задачи, ~2 месяца адаптации, 68% удовлетворённости чек-листом ([metrics.md](../metrics.md)).
- **Новые кандидаты в сценарии:** оборудование, вопросы по задачам, ИПР и матрица компетенций ([90-backlog.md](../scenarios/90-backlog.md)).
