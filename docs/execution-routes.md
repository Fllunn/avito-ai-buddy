# Контракт маршрутов

Проектируемый контракт утверждённого change; наличие этого документа само по себе не означает, что API реализован.

## Состояния

| Факт | Состояние маршрута | Состояние узла | Следующее действие |
|---|---|---|---|
| Принятие | queued | pending | Обработчик |
| Разрешённый контекст, поиск, фактическая модель | running | running/succeeded/skipped | Обработчик |
| Уточнение, карточка | waiting_user | waiting_user | Пользователь |
| Подтверждение версии | queued | succeeded | Очередь |
| Вызов сервиса | running | waiting_service | Сервис |
| Результат сохранён | completed | succeeded | Отдельное бизнес-согласование |
| Локальный или сервисный отказ | rejected | rejected | Исправление/контакт |
| Достоверный технический сбой | failed | failed | Разрешённое восстановление |
| Потерян ответ | reconciling | unknown | Сверка прежней попытки |
| Исчерпана сверка | manual_review | unknown | Ответственный |
| Отказ от черновика/истечение | cancelled | skipped | Новая карточка при необходимости |

Неизвестный исход не переводится в failed по клиентскому таймеру. Позднее created не отменяет approved. Частичный перенос сохраняет отдельные исходы каждой операции. Инструкция без просьбы действия заканчивается ответом без узлов отправки. Кнопка без LLM не создаёт узел модели.

## DTO и чтение

`GET /api/executions?limit=20&cursor=...&active=true`: собственные маршруты, сортировка `(started_at,id)` убывает, максимум 100. Cursor непрозрачен, пустой/ошибочный параметр отклоняется. Active выбирает по состоянию, независимо от возраста.

`GET /api/executions/{id}?after_sequence=0&limit=20`: snapshot (`id,scenario,state,current_node_id,revision,last_sequence,started_at,updated_at,nodes,edges,links,result_code`), `events,next_sequence,has_more,as_of,detail_complete`. next_sequence — последний выданный факт, last_sequence — последний факт снимка. Отфильтрованный факт сохраняет sequence с безопасным общим кодом. Узел: `id,kind,state,label_code,detail_code,service_code,started_at,finished_at`. Будущих времён нет.

Каждое чтение проверяет действующую сессию, включённого владельца и текущие права на связанные данные. Нет сессии — 401; чужой, скрытый или несуществующий id — общий 404. Общие коды: context, model, sources, validation, clarification, confirmation, queue, service, persistence, reconciliation, answer; названия сервисов только knowledge/access/time_off. Произвольные подписи, промпты, секреты и сырые payload не разрешены.

Совместимые необязательные execution_id/execution_ids дополняют accepted/job/chat/card. Старые ответы и бизнес-поля сохраняются. Отсутствующая связь означает отсутствие истории, не разрешает реконструкцию.

## Уникальность и атомарность

Run блокируется до выделения sequence/revision. `(run_id,fact_key)` уникален, `(run_id,sequence)` — первичный ключ. Ключ факта не включает lease. Link содержит тип и id с версией/номером попытки, серверное владение обязательно. Старый обработчик проверяет актуальный lease в существующей транзакции перед переходом. Финал маршрута атомарен с результатом попытки. Операционные часы UTC независимы от бизнес-даты.

## Реализованная корреляция и восстановление

Реализация: `backend/internal/execution/` — типизированные факты и детерминированный Memory; `storage/executions.go` — PostgreSQL; `storage/execution_runtime.go` — граница наблюдения. У Memory нет собственного worker: lease проверяется вызывающей транзакцией. Тесты Memory проверяют порядок/дедупликацию/конкуренцию/пагинацию/поздние факты; PostgreSQL и worker дополнительно проверяют lease и перезапуск.

Связи `message/job/card/attempt` создаются в транзакциях исходных объектов. У принятого сообщения есть стабильный маршрут обработки. Уточнение связывает его с исходным логическим запросом через `parent`; подтверждённые ранее факты обработки копируются с теми же ключами происхождения. Промежуточные события не меняют уже отправленную попытку и её исход. Самостоятельный новый вопрос сохраняет свой маршрут. Второе намерение имеет отдельный маршрут, общий message и устойчивый ordinal в версии message-связи; оно не наследует подтверждение первого.

Карточка хранит ссылки всех своих версий. Подтверждение добавляет попытку и её job. Повтор `client_message_id` возвращает прежнюю связь, конфликт содержимого остаётся 409. Прямая форма возвращает `execution_ids` сразу; чтение job, карточек и сообщений также дополняется этим необязательным массивом. У legacy-объектов массива может не быть. Отказ от черновика, замена и истечение завершаются без отправки; отказ повторной проверки показан как локальный.

Ключи фактов: `message:{id}:queued`, `job:{id}:{kind}:{state}:{operation}:{ordinal}`, `card:{id}:{version}:{outcome}`, `attempt:{attempt_id}:{job_id}:{outcome}`. Lease не входит в ключ. `operation` различает распознавание и выбор фрагментов; повторная сверка имеет свой номер. Сохранение ответа и карты опирается на авторитетное состояние карточки: повтор worker после сбоя ответа не превращает неподтверждённый черновик в завершённое действие.

Перенос имеет родительский run `transfer` и две связи `operation_parent`, упорядоченные ordinal 1/2. Каждая операция хранит отдельные карточку, подтверждение и попытку. Снимок родителя содержит `children` — два безопасных снимка в той же repeatable-read транзакции. Revision родителя меняется атомарно при новых фактах детей. Частичный результат остаётся `partial`; unknown/manual_review не превращаются в успех. Поздний результат отправки не откатывает авторитетную версию сервисного объекта. Бизнес-ожидание согласования читается из заявки, завершённая отправка не опрашивается бесконечно.

## Деградация и откат

Промежуточная телеметрия записывается отдельно либо под savepoint. Её сбой оставляет `detail_complete=false` и не останавливает безопасный ответ. Отсутствующие этапы не дорисовываются. Обязательные переходы карточки, попытки и результата сохраняются транзакционно: сбой финального факта откатывает результат, а возможный внешний эффект остаётся под защитой прежнего operation_key и сверки. Наблюдаемость не разрешает повтор мутации.

Миграции 005/006 аддитивны, не изменяют историю старых операций и не переписывают 003/004. Безопасный откат — вернуть предыдущий клиент и обработчики, оставив дополнительные таблицы. Бизнес-объекты, попытки и ключи не удалять; destructive down-миграция не требуется.

## Клиентский опрос

`useExecutions` — один координатор TanStack Query на сессию. Он читает свежую историю и все страницы active-фильтра, затем страницы событий каждого run по `next_sequence`, объединяя события по sequence и игнорируя старые revision. Ссылки `parent/operation_parent` восстанавливают старые исходные запросы за пределами первой страницы истории. Один run не опрашивается отдельно каждым представлением карты.

Active-фильтр включает queued/running/reconciling, ожидание пользователя и ручную проверку для восстановления. Сетевой таймер 1 с включается только для обработки queued/running/reconciling либо существующего активного job; waiting_user/manual_review/completed его останавливают. Возврат фокуса обновляет список. Отдельные часы интерфейса отслеживают давность успешного ответа, а не длительность этапа: после 5 с у активного run появляется предупреждение. Ошибка карты сохраняет последний снимок и независимые бизнес-карточки. Смена сессии отменяет HTTP-запросы, очищает Query/Zustand и поколение координатора; поздний ответ прежнего поколения отбрасывается.

Фиксированные шаблоны карты используют только разрешённые kind: ориентирование — очередь/контекст/фактическая модель/источник/ответ; доступ и отгул — применимые уточнения/подтверждение/очередь/проверка/сервис/сохранение/сверка. Неприменимые узлы отсутствуют; фактически пропущенный узел имеет skipped. Родитель переноса раскрывает две подцепочки. Компактный вид, подробности и поза маскота читают один снимок. Проценты и искусственные задержки не используются.
