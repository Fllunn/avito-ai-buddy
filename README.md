# AI-buddy — ИИ-наставник для стажёров

Прототип ИИ-помощника, который помогает стажёру Авито освоиться в новой команде: отвечает на рабочие вопросы, ведёт по этапам адаптации и выполняет действия через корпоративные сервисы (имитации).

Кейс хакатона Hack&Change 2026 (Avito Start). Описание кейса — [docs/case/brief.md](docs/case/brief.md).

## Текущее состояние разработки

Реализация идёт по утверждённому change [build-onboarding-prototype](openspec/changes/build-onboarding-prototype/tasks.md). Работают сборка и запуск Go API/имитаций, общая конфигурация и Clock, PostgreSQL с раздельными базами/ролями, Redis и React/TypeScript-каркас. Стартовый экран перенесён из переданного ZIP Figma Make; [происхождение дизайна и отличия](docs/design/README.md).

Демо-вход, выход и `/api/me` работают на бэкенде; чат, план и бизнес-операции ещё не реализованы. Поле ввода и кнопки на стартовом экране пока отключены с явным сообщением; успешные операции не имитируются в браузере. Процессные health checks не означают готовность этих сценариев.

## Быстрый старт (Docker)

Нужны Docker Engine и Docker Compose с поддержкой `--wait` и YAML `!reset` (проверено на Engine 28.3.3). В корне:

```bash
cp .env.example .env
# При необходимости заменить локальные демонстрационные пароли в .env.
docker compose up -d --build --wait
docker compose ps
```

Стартовый экран: [http://localhost:5173](http://localhost:5173). API: [healthz](http://localhost:8080/healthz), имитации: [healthz](http://localhost:8081/healthz). PostgreSQL опубликован только на `127.0.0.1:15432`, Redis — на `127.0.0.1:16379`.

```bash
docker compose stop                 # остановить процессы, контейнеры и данные остаются
docker compose up -d --wait          # запустить снова
docker compose down                 # убрать контейнеры и сеть, сохранить тома
docker compose up -d --wait          # восстановить контейнеры с прежними данными
```

`make up` и `make down` — сокращения для запуска со сборкой и остановки с сохранением томов. Сброс всего демо будет реализован отдельно (задача 7.6); сейчас не используйте удаление томов основного стенда для выборочного сброса сервисов.

PostgreSQL создаёт базы `buddy_api` и `buddy_mocks` с разными владельцами. Права PUBLIC на подключение к этим базам отозваны; роли не имеют SUPERUSER/CREATEDB/CREATEROLE. Пароли задаются только окружением. Инициализация выполняется один раз на пустом томе; смена переменных не меняет пароль уже созданной роли. API при старте применяет версионированные миграции, а в `DEMO_MODE=true` — повторяемый сид M-0. Повторный запуск не сбрасывает изменённый прогресс и сессии. Таблицы имитаций добавляются отдельно, доступ к БД помощника им не предоставляется.

```bash
make infra-check
```

Проверка создаёт отдельный проект `ai-buddy-infra-check`, не публикует порты, проверяет health checks, запрет подключения роли к чужой БД, сохранение контрольной записи PostgreSQL и ключа Redis после `stop/up` и `down/up`. По завершении удаляет только свои одноразовые тестовые контейнеры и тома. Основной проект `ai-buddy` не затрагивается.

### Демо-профили и серверные сессии

Все имена синтетические. `alina` — стажёр «Платежей» (старт 09.11.2026), `maxim` — стажёр «Поиска» (02.11.2026); `igor`/`sergey` — наставники, `olga`/`anna` — руководители, `daria` — HR BP. В сиде 21 шаг с назначениями, 8 документов и 11 ресурсов; материалы помечены как демонстрационные. Сид `ON CONFLICT DO NOTHING` не возвращает изменения пользователя к исходному состоянию. Полный согласованный сброс будет доступен в задаче 7.6; до этого данные сохраняются в томе.

После пересборки API можно проверить серверный вход (интерфейс входа пока не подключён):

```bash
curl -c /tmp/buddy-cookies -H 'Origin: http://localhost:5173' \
  -H 'Content-Type: application/json' -d '{"user_id":"alina"}' \
  http://localhost:8080/api/demo/session
curl -b /tmp/buddy-cookies http://localhost:8080/api/me
curl -b /tmp/buddy-cookies -X DELETE -H 'Origin: http://localhost:5173' \
  http://localhost:8080/api/session
```

Вход доступен только при `DEMO_MODE=true` и выбирает серверный профиль, без пароля; это демонстрация, не корпоративная авторизация. Неизвестные поля (`role`, `team_id` и др.) отклоняются. Cookie `buddy_session` имеет HttpOnly, SameSite=Lax и Path=/; Secure включается для HTTPS origin. В PostgreSQL сохраняется только SHA-256 токена. При смене профиля старая сессия удаляется атомарно, при выходе cookie и серверная сессия удаляются. Срок проверяется серверными часами, включая границу истечения. После отключения профиля его сессия перестаёт работать. Мутации требуют точного `Origin` из `ALLOWED_ORIGIN`; CORS с credentials разрешён только этому origin.

### Локальная разработка frontend

```bash
cd frontend
npm ci
npm run dev
```

Vite слушает `127.0.0.1:5173` со строгим портом. Если Compose frontend уже работает, сначала остановите его: `docker compose stop frontend`. Для production-сборки: `npm run build`. В Docker статический `dist/` обслуживает Nginx; `/api/` проксируется к Go API на том же origin. Настройка отдельного API base URL будет добавлена вместе с API-клиентом (5.1).

### Локальная проверка Go-каркаса

Нужен Go 1.27.0. PostgreSQL-драйвер: `github.com/jackc/pgx/v5 v5.7.6`, зависимости закреплены в `go.mod`/`go.sum`; [официальный API пула и транзакций](https://pkg.go.dev/github.com/jackc/pgx/v5@v5.7.6/pgxpool). В корне:

```bash
make test-backend test-mocks
npm --prefix frontend ci
make build
cp .env.example .env
# Указать собственный локальный SERVICE_SECRET в .env.
set -a
source .env
set +a
./backend/bin/server
```

В другом терминале:

```bash
curl http://127.0.0.1:8080/healthz
curl -i http://127.0.0.1:8080/readyz
```

`healthz` возвращает только живой процесс (`stage=bootstrap`); `readyz` намеренно отвечает 503 `BOOTSTRAP_ONLY`: БД и бизнес-маршруты ещё не подключены. Конфигурация проверяется до открытия порта. Остановка — Ctrl+C, ожидание завершения запросов ограничено 5 с.

Имитации используют тот же конфигуратор и часы. Для проверки второго процесса:

```bash
HTTP_ADDR=127.0.0.1:8081 DATABASE_URL=postgres://buddy_mocks:replace-local-mocks-demo-password@localhost:15432/buddy_mocks ./mocks/bin/server
```

Go-процессы пока только валидируют URL БД: доменные репозитории не подключены. Compose уже создаёт базы и роли; их доступность и изоляция проверяются отдельно инфраструктурным тестом.

## Конфигурация

Пример без реальных секретов — [.env.example](.env.example). Загрузка `.env` выполняется оболочкой; код читает только окружение.

| Переменная | Значение по умолчанию / правило |
|---|---|
| `HTTP_ADDR` | `:8080`, host:port, порт 1–65535 |
| `DATABASE_URL` | обязательный PostgreSQL URL с хостом и базой, отдельный для каждого процесса |
| `REDIS_ADDR` | `localhost:6379`, обязательный хост и числовой порт |
| `ALLOWED_ORIGIN` | `http://localhost:5173`, один HTTP(S) origin без пути, query, credentials и wildcard |
| `MOCK_URL` | `http://localhost:8081`, HTTP(S) origin |
| `SERVICE_SECRET` | обязателен, минимум 32 байта; не выводится в ошибках |
| `DEMO_MODE` | `false`, явное включение демо через `true` |
| `DEMO_NOW` | пусто — системное время; RFC3339 — фиксированное время, только при `DEMO_MODE=true` |
| `DEMO_TIMEZONE` | `Asia/Yekaterinburg`, явная IANA-зона либо UTC, не `Local` |
| `LLM_PROVIDER` | только `fake`; внешний адаптер ещё не реализован |
| `LLM_MODEL` | пусто для fake; модель, сервис и переменная ключа будут выбраны отдельным ADR |
| `CARD_TTL`, `STEP_CONFIRMATION_TTL`, `SESSION_TTL` | `24h`, `5m`, `8h` |
| `LLM_TIMEOUT`, `SERVICE_TIMEOUT`, `CLIENT_POLL_INTERVAL` | `20s`, `3s`, `1s` |
| `RECONCILE_DELAYS` | `1s,3s,10s,30s,60s`, ровно пять возрастающих положительных длительностей |

Длительности задаются в формате Go (`s`, `m`, `h`), ноль и отрицательные значения отклоняются. Пока это контракт будущих маршрутов: фактического вызова LLM или сервиса в каркасе нет. Ошибки конфигурации содержат имя настройки без переданного значения.

Время хранится как UTC; гражданская дата и семидневный период считаются в заданной зоне. До даты старта `Week` возвращает 0. Фиксированные часы не движутся сами: для теста границы времени создаётся новый `clock.Fixed`. API и имитации должны получать одинаковые `DEMO_NOW`/`DEMO_TIMEZONE`.

## Тесты и покрытие

```bash
make test                     # Go с race detector и Vitest, без настоящих LLM/сервисов
make coverage-backend-native  # backend/coverage.out и нативная статистика операторов Go
make coverage                 # три модуля + взвешенный отчёт исполняемых строк
```

Тесты проверяют конфигурацию, безопасные ошибки, системные/фиксированные часы, границу полуночи, семидневные периоды, DST, високосный год и HTTP health checks. `cmd/` содержит только запуск и завершение процесса; прикладной код — в `backend/platform/`.

`make coverage` запускает тесты с race detector, проверяет сам алгоритм подсчёта и формирует `coverage/summary.json`: backend, frontend, mocks и сумму покрытых/всех строк. Для каждого модуля и суммы требуется строго **> 80%**; ровно 80% и пустой модуль дают ошибку. Нативные Go-профили — `coverage/{backend,mocks}.out`, статистика операторов — `coverage/{backend,mocks}-native.txt`; frontend — `frontend/coverage/` (V8, LCOV, JSON). Это покрытие текущего кода, а не доказательство готовности бизнес-сценариев.

Для Go список исходников берётся через `go list ./...`, тестируются все пакеты с `-coverpkg=./...`. Неимпортированный пакет входит в знаменатель; отсутствие исполняемого исходника в профиле завершает проверку ошибкой. Повторы одного блока из разных тестовых процессов объединяются по факту исполнения. Исполняемая строка содержит токен внутри инструментированного блока, кроме комментариев и разделителей; строка покрыта только при исполнении **всех** относящихся к ней блоков. Нативная статистика операторов сохраняется отдельно. Фикстуры проверяют частичное покрытие общей строки, непроверенный пакет и точную границу 80%.

Исключены тесты, зависимости, `testdata`, сгенерированные Go-файлы с заголовком `Code generated … DO NOT EDIT.`, а также точные точки входа `cmd/server/main.go`, содержащие только подключение HTTP-обработчика к общему процессу. Добавление логики в точку входа автоматически отменяет исключение. Жизненный цикл HTTP-процесса учитывается в backend; обработчик имитаций — в mocks. На frontend включены все `src/**/*.{ts,tsx}`, кроме тестов и `main.tsx`, который подключает стили и монтирует React. Для тестов HTTP-жизненного цикла нужны разрешённые локальные сокеты. `make coverage` автоматически поднимает PostgreSQL 16.6 в отдельном проекте `ai-buddy-test-<pid>` со случайным локальным портом и удаляет его тестовый том после проверки. Основной стенд не затрагивается. `make integration-test` запускает Go-проверки с той же изолированной БД. Без тестового URL обычный `make test` пропускает PostgreSQL-проверки с явным сообщением; итоговым прогоном считается `make coverage`.
